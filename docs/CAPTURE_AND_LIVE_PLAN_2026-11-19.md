## 使用入口

- 在「屏幕捕获」选择窗口或显示器，点「预览并拖拽」。拖边缘调整范围，拖框内移动，点「应用裁剪」后开始用新范围采集。
- 在「设置」的录制区填写分段秒数、MiB 或两者。达到任一限制后等关键帧，分段大小可能超过设置值。每段使用同一编码时间线并独立封装。
- 全屏按 Home 打开专业参数或节点画布及性能面板。耗时来自当前处理图和 CPU 调度观测，平均值与 P95 的口径分别标明。
- 在「播放地址」打开 HTTP／HTTPS／RTSP 或 RTP／UDP MPEG-TS 地址。组播地址需要端口，多网卡时可使用 FFmpeg 支持的 `localaddr` 参数。打开直播前可选择 1、2 或 5 分钟时移窗口。播放器进度条可以回看并返回直播边缘，压缩包缓存有 256 MiB 上限。

## 修复边界

- #121 在 DirectShow 视频接收端确认空压缩样本并跳过，原始视频短包、空压缩音频包和真正的解码错误继续按各自的契约处理。
- #126 用实际显示刷新周期约束 60→30 后的 2X 生成帧等待，留出真实帧的显示容量。内容去重链路使用已有回调抖动估计。依据为软件提交和时序模型。
- #150/#170 采集音频启动和重锚时保留一块回调余量，连续 500 ms 的同向大偏差才触发重锚，防止设备时钟倒退造成无符号下溢。实卡和软件注入结果分别记录。
- #145 Ada 中档使用独立 CUDA 上下文，检测到异步失败时释放交给 D3D12 的等待。SDK 主机接口的模拟拒绝可以复测同进程恢复，真实 CUDA 700／驱动重置依赖报告人的显卡和驱动。
- #164 的转储记录 D3D12Core 访问冲突。FSR 修正失败初始化、资源描述和可释放的模块引用。#169 缩小 XeSS 对 swapchain backbuffer 的资源标注范围并验证指导纹理尺寸。原报告硬件的根因仍需该组合复测。
