- **背景**：为迎接 GTA6，用户要求参考两张封面图（日落天空：靛蓝 → 淡紫 → 粉 → 桃橙，深紫阴影，白色霓虹字）做一套"高级不丑"的渐变新配色，并能在设置里切回现在的版本。
- **分支与基线**：分支 `claude/dusk-palette-20261114`，基于 main `20955b5`。
- **目录**：工作树 `worktrees/claude-dusk-palette-20261114`，构建 `build/claude-dusk-palette-20261114`（标签 2.1.6-dusk-palette-test）。
- **状态**：未提交，未合 main，未 push / 发布。

## 做了什么

### 配色

`设置 → 外观 → 界面配色`：
- **日落**：新配色，默认。
- **经典**：原配色。经典下所有颜色值与原型逐一相同，切换不影响播放和增强设置。

| 项 | 经典（原样） | 日落 |
|---|---|---|
| 底色 / 卡片 | 中性黑灰（#070709 … #24242A） | 同深度的低饱和靛紫（#100E1D … #262238），描边带淡紫 |
| 文字 | #F3F3F5 | 淡紫白 #F7F4FC |
| 强调色（橙） | #FF8A3D 平涂 | 日落粉 #F287A7；填充为桃橙 #F0B17B → 粉 #EF6FA3 渐变，进度条再延到淡紫 #BB96F3 |
| 强调色（白） | 白色光晕 | 霓虹白 #FFF6FB，粉色光晕 |
| 正常状态 | 绿 #3DDC84 | 薄荷青 #5ED4B2 |
| 警告 / 错误 | 原值 | 原值（不和粉色强调混淆） |
| 窗口背景 | 灰色径向渐变图 | 暮色天空图：上靛蓝、中紫、下梅紫，右下桃色、左下品红的低亮度霞光 |

### 实现

- **`Theme.qml`**：
  - 新增 `paletteName` 和 `dusk`；各颜色在两套配色之间切换。
  - `accentGradient`、`accentFrom/To/Far`：渐变强调色。
  - `backdropImage`：按配色和"背景渐变强度"选择背景图。
  - `shade(r,g,b,a)`：组件里写死的深色中性色，经典下原值不变，日落下同深度偏靛紫。用于电影条、极简页、节点画布、顶部栏、快速面板。
- **新组件 `VAccentFill.qml`**：平涂强调色，或日落渐变。
  - 用于开关（打开时）、滑块填充、主按钮、两条进度条（经典下仍为白色）。
  - 滑块和进度条的渐变铺满整条轨道，填多少就露出多少颜色，不会挤在已填部分里。
- **背景图**：新增 `tools/qt_probe/make-backdrop-dusk.py`，生成 `backdrop-dusk.png` / `backdrop-dusk-strong.png`。
  - 方法同原生成器：浮点计算、固定种子、三角抖动，防暗部色带。
  - "背景渐变强度"的无 / 轻 / 中照常生效。
- **设置页**：
  - 外观首行增加"界面配色"切换。
  - 强调色色块在日落下显示渐变 / 霓虹白。
  - 背景强度的说明随配色变化。
- **其他**：
  - 偏好键 `palette`（`dusk` / `classic`），在 `Preferences.cpp` 中校验；未设置时为日落。
  - 节点连线高亮在日落下跟随强调色。
- **词库**：新增 6 条，三种语言均有翻译。
- **没有用到 GTA 的任何美术素材、标志或名称**：只参考了颜色气质，数值是自己定的。

### 饱和度下调（用户反馈：饱和度有点偏高）

- **原则**：色相和明度不变，只降低饱和度，所以还是同一套配色，只是更沉稳。
- **底色、卡片与背景图**：按亮度保持的方式降到 0.72。背景生成器里的参数是 `SATURATION = 0.72`，原来是 1.0。
- **强调色与渐变**：HLS 饱和度降到 0.8。
- **其他**：`shade()` 的靛紫偏移由 (+3,−2,+20) 改为 (+2,−1,+14)；首页呼吸光改为 #F396CE。
- **新旧数值**：上表已是新值。旧值依次为 #100D22 … #27213F、#F8F3FF、#FF7AA2、#FFB06C → #FF5FA0 → #B98AFF、#4FE3B8。
- **对比图**：`reports/claude-dusk-palette-20261114/dusk-saturation-before-after.png`。

### 新 Logo（用户提供）

- **用法**：日落配色下，首页大图标、顶部栏按钮、设置 → 关于都换成用户给的新 Logo：像素手柄，淡紫 → 粉 → 桃色渐变，带霓虹光晕。经典配色仍是原来的白色 Logo（`Theme.logoImage`）。
- **原图**：原样保存为 `assets/veyra-logo-dusk.webp`（1254×1254，背景透明，光晕本身在透明通道里，SHA256 a9b899d2…）。
- **`tools/qt_probe/make-logo-dusk.py`**：从原图生成 `qml/Veyra/logo-dusk.png`。
  - 尺寸 720×480，与 `logo.png` 同为 3:2 画布，并且是它的 2 倍。
  - 手柄主体放在旧 Logo 形状所占的同一位置（宽度 75%、居中），所以三处布局都不变。
  - 光晕落在边距里，只有 0.14% 的极淡外雾被裁掉。
  - 用预乘透明度缩放，光晕边缘没有黑边。
- **首页呼吸光**：日落下改成淡粉色（不透明度 0.22–0.42），经典下仍是白色。
- **未改**：程序文件图标和任务栏图标（`assets/veyra.ico`，编进 exe）。

## 首页字标、启动动画与启动音乐（2026-11-15）

- **用户要求（按先后）**：
  - 日落主题下，首页的手柄图标和 "Veyra NR Video" 换成用户给的 "Veyra NR" 字标，饱和度稍降、适配主题；
  - 开软件时播放一段"非常牛逼"的入场动画，可参考用户录的 GTA6 官方 Logo 出场视频；
  - 光效不要有塑料感；把字母拆开做视差；缓入缓出要更"炸"；
  - 启动时播放用户给的 BGM 并让动画卡点，只播一次、不循环，打开任意播放源后自动暂停，界面角落放一个关闭声音的地方。
- **字标**：原图原样保存为 `assets/veyra-wordmark-dusk.webp`（1254×1254，透明背景，sRGB，SHA256 702e2ad8…）。`tools/qt_probe/make-wordmark-dusk.py` 生成以下文件：
  - `wordmark-dusk.png`：OKLCH 色度 ×0.8，色相和明度不变（与强调色同一比例），裁到字形，1164×969。去掉了抠图残留的背景雾点：离字形 6px 以外、alpha<16 的 22668 个像素。
  - `wordmark-dusk-glow.png`：同色柔光。软件绘制没有 MultiEffect，所以预先烘焙。
  - `wordmark-dusk-n.png`、`wordmark-dusk-r.png`、`wordmark-dusk-veyra.png`：三层视差。
    - 拆分：“Veyra” 与 N、R 在 y=520 平切对接，只有 y 的尾巴压在 N、R 上；N 与 R 在 x=635 的竖缝处分开。
    - 尾巴：在手画轮廓内按图像边缘填色抠出，外扩 4px，连同贴边阴影一起随尾巴移动。
    - 补画：被尾巴挡住的部分按纸片分区（N 顶部紫带、N 里的棕榈场景、R）分别做调和填充，露出来时像尾巴的投影。
    - 校验：三层叠回原位，与原图只在尾巴边缘 1px 有差异，其余 ≤3.6/255（舍入误差）。
- **首页**：
  - 日落配色下，手柄和标题换成字标。高度为页面高度的 0.24，限制在 130–210px；背后是烘焙光晕，呼吸透明度 0.16–0.30。
  - 经典配色首页完全不变，截图核对。
- **入场动画 `DuskIntro.qml`**：
  - 时长与节拍：3.26 秒，卡 BGM 开头的实测节拍（0.16、0.64、0.79、0.88、1.12 秒最强拍、3.26 秒）。
  - 入场：夜色海面上，N、R、“Veyra” 三层依次从暗处、从靠近镜头的位置漂入，再加速冲下，在各自的拍上急停（N 0.64、R 0.79、“Veyra” 1.12），带挤压回弹。每次落位镜头都有冲击，最后一下带抖动。这一版回应了"不够炸"：不再缓停，而是加速撞拍。
  - 场景：最强拍时地平线点亮，随后天空变暖、条纹太阳升起、余烬上飘。镜头持续推近、横移，三层始终有相对错动，形成视差。
  - 交接：2.7–3.26 秒，三层飞到首页字标的位置（近层拖后），太阳沉入海中，场景溶解成首页。最后一帧就是首页字标本身的像素，无缝交接。
  - 参考范围：用户的 GTA6 Logo 录屏只借鉴了"快速后拉后静止"的节奏，没有使用它的标志、画面或任何素材。
  - 光效：按用户反馈去掉了白色过曝、扫光和镜头光斑（塑料感），改为从暗处曝光，加柔光、胶片颗粒和暗角。
  - 交互：单击或按任意键跳过（落位前直接淡出，落位后以 2.5 倍速收尾）；拖动可以移动窗口；打开任何来源或切换页面时立即淡出。
  - 播放条件：日落配色、从首页启动、没关"启动动画"、没开"减少动画"、没有测试开关。设置 → 外观新增"启动动画"开关。
  - 时钟：一个时钟驱动全部画面；有音乐时以音乐的播放位置为时钟。
  - 绘制：软件绘制下只用 Image、Rectangle、裁剪、透明度和变换；光晕、颗粒、暗角都是预烘焙图（`tools/qt_probe/make-intro-dusk.py`）。
- **启动音乐**：
  - 新组件 `StartupMusic`（`include/veyra/ui/StartupMusic.h`、`src/ui/StartupMusic.cpp`，独立小库 `veyra_startup_music`）：用 Media Foundation 媒体引擎的纯音频模式，靠 Windows 自带的 MP3 解码，链接的是程序已在用的 mfplat、mfuuid。
  - 播放规则：只播一次，不循环。播放结束、出错或暂停后释放音频设备。
  - 文件位置：读程序目录下的 `media/startup-music.mp3`；没有这个文件就不放音乐，动画照常播放。
  - 版权：用户这首 BGM（115 秒，128kbps，没有标题和作者信息，来源与授权未知）**没有进源码仓库，也没有进任何包**，只复制到了测试 stage。公开发布前需要用户确认版权。
  - 自动暂停：打开任意播放源（`veyra.hasSource` 变为真）即暂停，之后不再继续。
  - 静音按钮：在首页右下角，音乐播放时显示，动画期间也能点。点击切换静音并记为偏好。
  - 设置：外观页新增"启动音乐"开关，与按钮共用偏好 `introMusic`。
  - 音量：取播放器的音量。
- **偏好与词库**：新增偏好 `introAnimation`、`introMusic`，未设置时为开；词库新增 8 条，三种语言齐全。

**真实程序**：
- 条件：测试 stage、独立配置、进程内抓图、不模拟输入；自动测试时音乐以静音状态播放。
- 结果：14 个场景全部通过，无 QML 错误。
- 帧率：
  - 软件绘制 1280×800：3.26 秒内 207 帧，约 63 帧/秒（软件绘制的上限），最差一帧 28ms。
  - 软件绘制 2400×1300：206 帧。
  - GPU 绘制：1034 帧（跟随 320Hz 屏）。
- 卡点：每 0.2 秒采样一次，动画时钟与音乐位置相差 0–1ms。
- 行为：
  - 跳过：落位后跳过，以 2.5 倍速收尾。
  - 切页：立即淡出。
  - 经典配色或关掉"启动动画"：不播放。
  - 关掉"启动音乐"或缺少音乐文件：动画照常。
  - 只播一次：用 4 秒音频代替时，播放结束（ended）后没有循环。
  - 动画结束后打开文件：音乐在 4.17 秒打开文件，4.53 秒暂停。
  - 带文件启动：动画不播放，音乐在 0 秒暂停。
  - 静音按钮：按钮处理函数切换静音并写入偏好。
- 预览视频：`reports/claude-dusk-intro-20261115/intro-preview.mp4`，真实程序逐帧 60fps，配 BGM 前 3.8 秒。
- 未验证：其他显卡、高 DPI、用户的主观观感。

**测试中的意外**：
- 第一版按钮测试想用音量 0 来静音，但播放器音量是异步生效的，BGM 实际以 100% 音量从扬声器放了约 7 秒（中途被测试点了一次静音）。之后所有测试都在启动前就设为静音。
- 4 秒短音频场景里，测试窗口右下角的按钮被一次真实点击点到（日志为 unmuted (button)），放出约 0.3 秒很轻的 330Hz 测试音。
