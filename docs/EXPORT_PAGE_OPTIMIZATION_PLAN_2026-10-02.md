## 页面和队列交互

保留现有深色三栏结构：左侧管理文件，中间预览与入出点，右侧设置与开始操作。

| 区域 | 拟定行为 |
|---|---|
| 左侧顶部 | “文件队列 N”及“添加文件”；支持多选和拖入文件。添加只登记文件和异步读取信息，不导出、不弹输出目录，也不强制切走正在预览的文件 |
| 左侧列表 | 可滚动、虚拟化的 ListView；显示拖动柄、缩略图、文件名、时长、状态与删除按钮。单击文件选中并在中间预览；预览选择与执行中的任务分别标识 |
| 列表管理 | 空闲时可单项移除、清空列表、拖动排序；这些操作只移除记录。运行中可调整等待项；当前任务锁定，需先取消再移除。“清空队列”在运行时改为“清空等待” |
| 中间 | 显示所选文件，入点/出点归属于该文件。新增文件默认整片；切换预览时保存并恢复该项范围。预览另一文件不更改已经提交的导出输入和参数 |
| 右侧 | 分开呈现封装、视频编码、输出尺寸、质量、增强预设、音轨、字幕、保存目录。分辨率的 8 段按钮改成现有风格的下拉选择；多轨选项单独占行 |
| 右侧底部 | 进度、当前第几项、当前任务状态和“开始导出 N 项”固定在底部；上方设置区纵向滚动。CQ 显示恒定质量，避免同时把无效 Mbps 展示为正在使用的码率 |

正常窗口沿用三栏。低于三栏可用宽度时建议改为导出页内部“文件 / 预览 / 设置”切换，底部任务状态仍可达；不通过修改全局最小窗口尺寸掩盖布局问题。现有主窗口允许 720×260，验收必须覆盖这个下限及常用窗口、100%/125%/150%/200% DPI。控件尺寸采用明确的布局约束，依据 [Qt Quick 布局说明](https://doc.qt.io/qt-6/qtquicklayouts-overview.html)核对 implicit size、minimum size 和可分配空间。

导出页和 `Main.qml` 的原生视频区域使用同一份导出布局尺寸/断点计算，初始化时提供确定的非零矩形；隐藏预览时同步隐藏对应视频区域。保留单一 videoHost。验证切页、打开文件首帧和 DPI 切换，防止视频覆盖按钮或出现 1×1 交换链。

### 队列执行规则

1. 点击开始时才确定输出目录、预检文件并冻结本批设置。增强预设、编码/封装/质量为批次默认值；每项保存自己的剪辑范围和轨道选择。导出中修改预览设置不改变本批任务。
2. 一次只运行一个导出 worker，按列表顺序逐项完成。继续复用既有 worker 隔离和增强图，不创建多套 NGX 或多个并行 GPU 导出。
3. 每项有稳定 itemId，每次尝试有独立 jobId，整批有 batchId。结果按 ID 归属；模型存储输入、输出、设置快照、状态、错误和进度，不按文件名猜状态。
4. Qt 列表只是任务模型的呈现。扩展现有 ExportJobManager 的队列管理与事件，避免 QML 维护一套顺序、C++ deque 又维护另一套顺序。使用 QAbstractListModel 适配任务模型，拖排按 ID 和插入位置完成。
5. 新增的待处理列表不能继续直接调用旧的“空闲即启动”enqueue。提供明确 add/startBatch/move/remove/clearWaiting/retry 接口；原调用方兼容包装只保留已有语义，不顺手改旧 Win32 行为。
6. 文件级失败标为失败并保留原因，继续后续文件；目标目录整体不可写、磁盘满等批次级问题停止调度，保留等待项。失败项由“重试”重新置为待处理，避免自动无限重试。
7. 点击取消停止本批自动调度、取消当前项并保留等待项。回收完成后再点开始，会从取消项重新编码，然后处理等待项；成功项跳过。暂停/继续仅保留当前进程，不与取消后从头重试混用。
8. 开始时冻结当前批次成员；运行中新增文件作为下一批待处理项，不偷偷加入当前批次。允许调整本批尚未开始项目的先后；已开始项的输入/参数不变。
9. 默认输出采用 `<原名>_veyra.<容器>`；同名文件、不同目录同名源、与输入同路径等在启动前解决并展示目标。预留名称且最终落盘不覆盖已有文件；多实例竞争要报告真实冲突。

本轮视频队列覆盖上述完整流程。图片模式保留现有单帧/批量图片入口并补完成提醒；混合视频与图片的一套执行队列不列入本次视频队列改造。

## 封装与音轨字幕

**MKV 是封装，不是编码。** 界面应为“封装：MP4 / MKV”和“视频编码：H.264 / HEVC”。MP4 可以包含多音轨和兼容的内嵌字幕；不能把多轨能力宣传成 MKV 独有。需要保留电影的原始音轨及复杂字幕时优先推荐 MKV。[FFmpeg 流映射说明](https://ffmpeg.org/ffmpeg.html#Stream-selection)、[Matroska 编码映射](https://www.matroska.org/technical/codec_specs.html)。

| 设置 | 方案 |
|---|---|
| 音轨 | “保留全部 / 选择轨道 / 不保留”，新任务建议保留全部；预览只播放当前选中的一条音轨，不能把预览选择误当导出筛选 |
| 内嵌字幕 | “保留全部 / 选择轨道 / 不保留”；默认保留建议与容器兼容预检一起呈现。独立可切换字幕轨保留，不增加字幕烧录流程 |
| MP4 | 兼容音轨可多条复制；兼容文本字幕可封装，部分输入需转为 mov_text。复杂 ASS 样式、PGS/VobSub 图片字幕不能承诺无损进入 MP4 |
| MKV | 优先复制兼容音轨、SRT、ASS/SSA、PGS 等轨道。保留 ASS 所需字体附件、轨道语言/标题、default/forced 标记。目标是兼容轨道的完整保留，不承诺任意 codec 都能直接复制 |
| 不兼容 | 开始前逐轨给出“复制 / 需转换 / 不支持”。明确建议切换 MKV或排除此轨；不能静默丢轨、降混、烧录或转码。用户明确选 MP4 时不能暗中更换扩展名 |

MKV 对部分 MP4 字幕如 mov_text 也未必支持直接 packet copy，必须按实际输入判断。字幕转换复用已有 FFmpeg 编解码能力并标明转换后的格式；复杂样式不能保真时推荐保留原兼容容器或明确提示。字体附件原样封装，不安装到系统、不执行附件。Matroska 的 ASS、PGS 与字体附件映射见[官方定义](https://www.matroska.org/technical/codec_specs.html#s_textass)。

### 后端实现

- 给导出作业增加 container、audioPolicy、subtitlePolicy 与所选轨道描述。映射到 FFmpeg 的 mp4/matroska muxer；不能只换文件后缀。worker 的 Shared 协议升级版本并验证字段，不能直接跨进程复制含指针的容器对象。“全部”在 worker 枚举全部适用流，不设一个隐含条数上限截断音轨。
- 将单 audioIndex/audioStream 改成明确的输入流到输出流映射。视频仍走现有 GPU 增强与 NVENC/MF 编码；音频、字幕、附件沿用 FFmpeg 库的压缩包处理。不接 raw video pipe、不增加常态 GPU 像素回读，不重新实现容器格式。
- 输出保留支持的轨道 codec 参数、声道布局、语言、标题和标记；AAC/AC3/EAC3/DTS/TrueHD/FLAC/PCM 等是否可复制按实际 muxer 和本机版本预检，不以“支持 MKV”代替逐轨兼容判断。
- 无剪辑时尽量原样复制附属轨道；剪辑时视频、所有音轨、字幕共用同一源时间基准并统一平移时间戳。原有声音偏移保持，不能把每条音轨各自强行归零。音频直接复制存在包边界精度，不宣称任意采样点精确裁切。
- 跨越入点的文字字幕需要保留并裁剪有效时段，不能因开始时间早于入点就整条丢弃；字幕末尾不得超出剪辑区间。PGS/VobSub 等还需保留解码初始化/显示状态并验证入点画面，不能把它们当成普通 SRT 包减时间戳。缺少可靠裁剪路径时在预检明确拒绝该组合，不能标整项验收完成。
- 复用 FFmpeg interleaved mux，设置有界缓冲；稀疏字幕不能阻塞音频输出，不把整段音轨或字幕提前读入无限队列。用短样本、长间隔字幕和长音轨分别验收。
- 复用现有 HDR/颜色与增强合同，不在本任务扩大 Dolby Vision、补帧后端或新视频编码支持；节点链离线导出仍按当前实际支持边界提示。

## 取消和重新导出

这部分先做，因为不稳定的单任务生命周期会破坏批量队列。

1. 增加“取消中/等待回收”状态，期间不能启动新 worker。停止新帧提交，按现有顺序停止编码、关闭封装、释放文件和 GPU 资源；保留当前有界退出超时及只针对本任务 Job Object 的兜底。
2. 区分“worker 报告了结果”和“进程已退出、父进程已回收”。只要进程或 IPC 句柄仍需处理，UI 调度就继续 poll；shared 终态不能单独关停轮询。最终终态由管理器在退出回收后发布，start 也应防御性回收已退出进程。
3. 每次尝试使用专属临时输出名，如 `.片名.veyra-<jobId>.partial`，并记录所属任务。失败/取消后只能清理自己创建的文件，且必须等 worker 退出、文件关闭。清理失败保留准确路径和原因，但不让历史 partial 永久阻塞新的尝试。
4. 既有同名 partial、其他任务 partial、源文件和已成功文件全部保留；不全目录扫描删除。开始下一次时创建新临时文件，成功关闭 mux 后再安全改为正式名，目标已存在则拒绝覆盖。
5. 启动失败立即读取/返回具体原因并通知界面，例如目标冲突、设置错误、设备错误；不再统一替换成“详见诊断”。任务行保留错误及对应日志路径。
6. 重试创建新的 jobId、cancel/pause 标志、计时和进度，不复用旧通信状态。取消发生在保存正式文件附近时，以实际安全落盘结果定义最终状态，不能出现已经成功却被删除或失败却播成功音。

本轮未运行原程序复现这个竞态，也未执行重试修复；上述结论分为已确认代码路径与待验证的竞态触发，不能写成“已修复”。

## 完成提示音

- 默认建议开启，提供“完成提示音”开关。使用 Windows 现成系统提示音 `MessageBeep(MB_OK)`，不引入新的媒体播放库。[Microsoft 接口说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-messagebeep)。
- 单文件导出成功响一次；批量全部成功后响一次，不在每个文件结束时连续响。已有图片批量入口在确认全部完成后采用相同通知规则。
- 依据管理器已回收后的真实成功事件，以 batchId/jobId 去重；不能监听 exportRunning 从 true 变 false 就播放，因为失败、取消也会产生同样变化。
- 部分失败显示成功/失败数量，不播全成功提示音。取消、失败、空队列和清空队列均不播。
- 声音调用异步、不阻塞 UI；由系统声音设置决定是否可闻，仍保留可见完成提示。开关关闭后不得触发声音。

## 审查结论和下一步

方案复用已有 worker、FFmpeg 与 Qt 组件，主要工作是把“文件清单、任务执行、预览选择”分清并建立可核对的结果归属。最大风险是取消回收竞态和带剪辑的字幕/多轨时间处理，工作量高于移动按钮或加 MKV 下拉框。

已做源码反向核对：没有把 MKV 当编码；没有把系统 FFmpeg 样本当产品通过；没有把“进程报告完成”当成“资源已回收”；没有用文件名或列表切换推断成功；没有把工作区隔离等同于未来无合并冲突。

下一步实施先建立本分支独立范围记录，稳定复现取消后的同路径重试与退出竞态，完成切片 1 后再接批量队列。本轮产品构建、QML 截图回归、真实 GPU 导出、提示音试听全部未执行。
