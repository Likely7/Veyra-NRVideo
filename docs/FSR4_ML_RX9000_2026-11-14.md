# FSR 4 ML 补帧给 RX 9000 用户默认启用（2026-11-14）

用户要求：“那你给它加进去啊，让9000用户用上”。分支 `claude/fsr4-ml-rx9000-20261114`（基于本地 main `2f0e499`），工作树、build、tests、logs、reports 都用同名任务目录。只在本机：没有合 main、没有 push、没有发布。

## 现状

FSR 4 ML 是 AMD 的 ML 帧生成，也就是 FSR Redstone 里的 ML 补帧。它从 2.0.0 起就在 Veyra 里，补帧后端菜单中叫“FSR 4 ML”：

- **运行库**：FidelityFX SDK 2.3.0 的 `amd_fidelityfx_framegeneration_dx12.dll` 4.0.1.2740。2.1.6 的两个包都带着它，位置是 `runtime_local/amd/fidelityfx/`。
- **显示条件**：只在名称含“RX 90”的 AMD 显卡上出现在菜单里。
- **倍率**：只支持 2X。
- **版本核对**：运行时按 AMD 提供方实际列出的版本选择 4.0.x，没有就不回落到 3.1 冒充 ML。在 N 卡上，提供方只列出 3.1.x。

RX 9000 用户以前“用不上”有三个原因：

1. 新配置默认选 FSR 3.1，ML 要自己去菜单里找。
2. 菜单上标着“实验”。
3. 提供方没有 ML 版（驱动不支持）或创建失败时，补帧会被整个关掉；播放中切换则会退回上一套参数。

## 改动

- **默认**：`defaultFrameGenerationBackend(vendor, rx9000)`，AMD RX 9000 的新配置默认用 FSR 4 ML；判断规则和菜单开关相同，都是名称含“RX 90”。保存过的选择不覆盖；保存的后端不可用时，优先改成 FSR 4 ML（在提供时），然后才是 FSR 3.1、XeSS。
- **回落**：`disableFailedBackend` 遇到 FSR 4 ML 补帧失败时，改用 FSR 3.1 并保持 2X，不再关闭补帧。FSR 3.1 也失败时，才按原样关闭补帧。
  - 播放中从可用的补帧切到 FSR 4 ML 时，同样改用 FSR 3.1，不再整套回退。
  - 提示文字改为“……已改用 FSR 3.1；原因见日志”；运行中失败时提示“FSR 4 ML 运行失败，已改用 FSR 3.1”。
  - 界面菜单随之显示 FSR 3.1，状态显示实际运行的提供方版本。
- **不变**：导出仍然是“不替换后端、不降低倍率”，FSR 4 ML 不可用时导出直接失败并说明原因。
- **菜单**：去掉“实验”，现为“FSR 4 ML · RX 9000”。提示改为“FSR 4 ML 需要支持的 RX 9000 和驱动，不可用时自动改用 FSR 3.1；尚未在 RX 9000 实卡上验证”。
- **词库**：原位改 2 条，新增 1 条；菜单标签已不含中文，按提取规则删掉对应条目。最终 2874 条，缺失 0，占位符问题 0。
- **测试**：
  - `veyra_repair_contract_tests` 新增 8 项：默认值、恢复顺序、ML→3.1→关闭的回落链。
  - `veyra_fg_settings_tests` 新增 `fsr4-fallback` 模式：从关闭补帧和从运行中的 FSR 3.1 两种状态请求 FSR 4 ML，都应用 FSR 3.1 2X 并继续生成帧。

## 验证（本机 RTX 5070，没有 RX 9000）

- **构建**：7 个目标 322.4 s 通过，标签 `2.1.6-fsr4-ml-test`。
- **单元测试**：修复合同 通过（316 checks 0 failures）；ANR 设置 通过（48 项；首跑时运行脚本漏传它要求的数据目录参数而退出码 2，补传后重跑）；界面合同 通过。
- **QML**：Totals: 208 passed, 0 failed, 0 skipped, 0 blacklisted, 46431ms。
- **图级 FSR 切换**（`veyra_fsr_switch_tests`）：通过。本机的 FSR 4 ML 在图初始化阶段被干净拒绝，同一窗口再开 FSR 3.1 正常，D3D12 调试层 0 错误。FSR4_UNSUPPORTED_ROLLBACK pass=1; FSR_SWITCH pass=1 cycles=18 generated=774 debugErrors=0
- **引擎级回落**（`veyra_fg_settings_tests fsr4-fallback`）：通过。FSR4_FALLBACK fromWorking=0 provider=3.1.6 warning=52; FSR4_FALLBACK fromWorking=1 provider=3.1.6 warning=52; This test checks settings, output counts and lifecycle; not target-card support or interpolation quality.

## 未验证

- **FSR 4 ML 补帧本身**：本机没有 RX 9000，从未在实卡上运行过，画质、耗时、显存都没有实测；本机只能验证 FSR 3.1 回落。
- **识别规则**：名称不含“RX 90”的 RDNA4 卡（如 Radeon AI PRO R9700）不会出现这个选项。
- **节点模式**：在节点模式下发生 ML→3.1 回落的界面表现没有实测。
- **老用户迁移**：已保存过 FSR 3.1 的 RX 9000 老用户不会被自动改成 FSR 4 ML，按项目“只改默认、不覆盖已保存偏好”的规则处理。
