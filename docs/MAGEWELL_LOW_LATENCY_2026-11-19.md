# 美乐威低延迟采集掉帧修复（2026-11-19）

用户提供的 `logs(3).rar` 含 11 月 17 日和 18 日的现场记录。复现设备是 Pro Capture HDMI 4K Plus，Veyra 2.1.9，3840×2160、P010、协商 59.94 FPS，独立 WASAPI 音频。

| 11 月 18 日 UTC | 视频来源 | 稳态回调中位数（FPS） | SDK 每 600 帧计数换算（FPS） | 提交中位数（FPS） |
|---|---|---:|---:|---:|
| 13:00:18 | DirectShow | 59.94 | — | 60 |
| 13:02:17 | SDK 低延迟 | 56.37 | 56.33 | 56 |
| 13:03:40 | DirectShow | 59.94 | — | 60 |
| 13:06:02 | SDK 低延迟 | 56.44 | 56.40 | 57 |

计算回调中位数时去掉了启动或停用 DirectShow 后的前两秒。11 月 17 日有四段 DirectShow 的回调中位数为 59.94 FPS，另外七段 SDK 低延迟为 56.59–57.78 FPS。较新的两段均已记录 DirectShow 成功停止。第二段低延迟会话的应用邮箱累计覆盖只有 8 帧，SDK 自己的 600 帧计数在处理前就已显示帧率下降。现场同时使用 60→30 与 VFG 2X，后端提交数字受源帧节拍影响，不能当作 HDMI 实际上屏帧率。

现有代码在同一捕获线程串行执行 DMA 完成、24,883,200 字节帧的拷贝及内容比较，再处理下一次通知。现场 SDK 报告从帧进卡到完成传输约 24–25 ms，超过 59.94 Hz 的 16.68 ms 帧周期。下一帧通常已经在板上开始缓冲，串行交付会再推迟下一次 DMA 提交。现场日志缺少各次请求的提交时间和丢失的板载帧序号，无法从已知数据量化 DMA、驱动与应用各自的耗时。

4K P010 在 59.94 FPS 的载荷约 1.49 GB/s，接近该卡官方约 1.6 GB/s 的 PCIe DMA 规格。实现按 [Magewell SDK 低延迟说明](https://www.magewell.com/developer/14/detail) 继续从正在缓冲的帧开始传输，并检查整帧完成。[Pro Capture HDMI 4K Plus 官方规格](https://www.magewell.com/static/tech-specs/USBCaptureHDMI4KPro/ProCaptureHDMI_4K_Plus.pdf)

采用两个锁页缓冲，DMA 同时只允许一笔。上一帧确认完成后，如果下一帧的通知已在等待，则在另一缓冲里先发起下一笔 DMA，上一帧随即交付既有单帧邮箱。无下一帧通知时立即交付，保持正常路径的等待边界。4K 大载荷改为每 256 行通知，NV12 与 1080p 等较小帧仍使用 64 行。带请求标识的完成检查确保 CPU 只读取正确的完整帧。传输超时后停止 SDK 并释放通道，之后才恢复普通采集。

使用独立 WASAPI 音频或无共享图音频时，SDK 从第一帧即独占视频采集。需要同一 DirectShow 图的音频时保留该路音频。保护条件是以卡内时间戳间隔和环形帧号共同核对，两个连续约两秒窗口都确认至少 3% 丢帧时，按当前协商格式自动切回 DirectShow。非匀速输入、格式变化和零星缺帧不会单独触发保护。回退日志记录原因、确认的缺帧数、实际 SDK 回调率和 DirectShow 启动结果。

本机测试从已验收的 `codex/claude-handoff-20261119` 快照开独立分支。实卡反馈数据及回归回执存 `E:/项目/Veyra/reports/codex-magewell-low-latency-20261119`，用户可从 `E:/项目/Veyra/tests/codex-magewell-low-latency-20261119/启动美乐威低延迟测试版.cmd` 启动独立配置。真实美乐威卡上的改后帧率、音画同步和端到端延迟需现场对照。

## 本地验证

- 完整构建启用原版 Magewell SDK 3.3.1.1596。测试目录中的 DLL 与依赖原件 SHA-256 一致。
- 59.94 Hz 调度模型模拟串行 DMA 和 CPU 拷贝争用。串行对照丢 85 帧，调整后的顺序连续交付 600 帧且没有漏帧。另覆盖暂无下一帧、终止或 DMA 未完成、连续缺帧、变节拍及信号切换。模型中的 DMA 与拷贝耗时是构造值。
- 采集格式、色彩、时间戳和 YUY2 GPU 验证通过。DLSS/VFG 2X 各验证 48 Hz 与 59.94 Hz 的合成 P010 序列，保留原 PTS，D3D12 调试错误为 0。
- SDK 原版 DLL 加载成功，本机枚举到 0 块 Pro Capture 卡。程序打开采集对话框的启动检查和 91 个着色器核验通过。未开启本机采集卡视频。
