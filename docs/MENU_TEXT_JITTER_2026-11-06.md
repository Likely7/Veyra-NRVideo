# 选框弹出时文字“抖两下”：软件绘制下弹簧到终点即停（2026-11-06）

- **分支**：`claude/menu-jitter-20261106`，工作树 `E:/项目/Veyra/worktrees/claude-menu-jitter-20261106`。
- **基线**：main `f1f8298`。
- **状态**：未提交，未合并，未 push/Release。

**用户要求**：“现在点击弹出的选框，文字总是会抖动两下，看起来蛮奇怪的，看看是啥问题。”

**来回经过**：

1. 用户先以为这个修复改掉了弹簧动画，叫停并要求保持原样。修复因此撤回过一次。
2. 随后用户更正：“我看错了……还是继续修复！修复效果是正确的。”
3. 本文是恢复后的最终结果。

## 原因

菜单 `VMenu` 打开时有两个动画：

- 缩放从 0.9 到 1，450 ms，用 `Theme.spring` 弹簧曲线；
- 向上移 8 像素，用同一条曲线。

**弹簧在终点附近来回越过终点**：曲线在 24% 冲到 1.043，44.1% 回到 0.99，60.7% 是 1.001，100% 才停在 1。所以缩放大约在 87、181、266 ms 越过 1，450 ms 停住。

**软件绘制把文字放在整像素上**：

- 软件绘制是 2.1.1 起的默认。它把文字横坐标向下取整：文字只要比停稳位置偏左一点点，就画到左边一整像素处。
- 这是根据测量推断的：缩放 1.0001 时偏 −0.005 像素，画成 −1；缩放 0.999 时偏 +0.05 像素，画成 0。

**两者叠加的结果**：菜单中线左边的文字在缩放大于 1 的两段时间里各左跳一次，中线右边的文字在缩放小于 1 时跳。这就是“抖两下”。

**GPU 绘制为什么不跳**：同一段弹簧只是不到半像素的平滑移动。2.0.7 用的是同一份 QML，界面是 GPU 绘制，所以没有这个现象。

**和 2026-10-26 那次修复的关系**：那次修的是首次打开时第一行字从 y=14 跳到 42 的布局问题，和这次不是同一个问题，那次的修复保留。

## 改动

**`qml/Veyra/VMenu.qml`**：

- 新属性 `holdLanding`，用软件绘制判断：`vySoftwareUi`，或 `GraphicsInfo.api === Software`。写法和 `VIcon`、`ProAddLayerButton` 相同。
- 打开时，弹簧第一次到达 1 后，界面上的缩放和位移就停在 1 和 0。
- 原来的 `enter`/`exit` 过渡、曲线和时长都不变；内部 `motion.s`/`dy` 仍完整走完弹簧，`motionScale` 探针照旧。
- 关闭动画不受影响：`aboutToHide` 时清掉落点标记。
- GPU 绘制下 `holdLanding` 为 false，画面和以前完全一样。

**`tests/qml/quick/tst_menu_layout.qml`**：

- 新增 `test_open_spring_lands_once`，分两行数据：
  - **软件这一行**：用菜单自身的绑定，确认弹簧原值仍会冲过 1.001；画出的缩放和位移不越过终点；文字只靠近、不远离，落点后与停稳位置一致；关闭仍会缩小。
  - **另一行**：关掉 `holdLanding`，确认画出的值就是完整弹簧。
  - 两行都检查绑定跟随渲染方式。
- `test_rendered_spring_text` 截取的是指定缩放下的画面，所以截图期间临时关掉 `holdLanding`。

## 验证

**构建**：`build/claude-menu-jitter-20261106`，按 main 配置，构建步骤只复制 QML。

**QtQuick 测试**，环境同 `scripts/acceptance/menu-amd-hdr-fix.py`：Windows 平台、私有临时目录和配置：

- 菜单两项测试在五种组合下全部通过：
  - 软件 100%、150%、200%：各 6 过，0 失败；
  - d3d12 100%、150%：各 5 过，0 失败，跳过 1 项（软件专用那一行）。
- 全套软件绘制：147 过，0 失败，跳过 1 项。跳过的是需要截图目录的 `test_rendered_spring_text`；它单独加截图目录运行，3 项通过，6 档缩放下文字位置随缩放变化，说明截图期间确实关掉了停住逻辑。

**真实程序录屏**：

- 程序是 2.1.2 测试包的私有副本，只换了 `VMenu.qml`（与 main 只差这一处）。屏幕 320 Hz，缩放 100%。
- 用注入的探针在 Pro 页把“超分后端”选框开、关 3 次，ffmpeg `ddagrab` 以 240 fps 无损录菜单区域，逐个不同帧跟踪“DLSS SR”这行字。

| 版本 | 软件绘制 | GPU 绘制 |
|---|---|---|
| 原版 | 3 次都在约 66–154 ms 和 250–420 ms 左移 1 像素再回来 | 平滑，约 100 ms 时越过终点 0.2 像素，约 250 ms 停稳 |
| 修复 | 3 次都一路靠拢，约 50–67 ms 落点，之后只剩淡入，没有出现 −1 | 与原版相同 |

- 第一段 GPU 修复录像里，第一次打开约 250 ms 后菜单就被关闭了，是偶发。GPU 绘制下这次修复不起作用；重录一次，3 次打开都正常。

- **缩放比例**：真实程序只在 100% 缩放下录了屏；150%、200% 只在 QtQuick 测试里验证过逻辑。
