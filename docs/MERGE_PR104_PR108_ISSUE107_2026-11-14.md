## Issue #107

反馈：RTX 5070 Ti 跑游戏，RTX 5070 跑 Veyra，两块卡都是 PCIe 5.0 x8。游戏稳定 60 fps，但 Veyra 采集在关闭 NR 时只有 50 多帧，开一层 NR 掉到 30 多帧，副卡功耗不超过约 170 W。建议：NR 期间保持原帧率、异步 NR、优化同步和跨卡传输、多显卡（包括 NVIDIA 配 AMD）、NR 之后补帧。

### 本机复现

本机只有一块 NVIDIA，没有第二块 NVIDIA 可测。条件如下：

- RTX 5070 接 2560x1440、320 Hz 的显示器。Windows HDR 开着，所以采集格式是 scRGB FP16。
- AMD 核显没有接显示器。
- 片源是自写的 `fps_source.exe`，每秒精确呈现 60 张不同的画面。
- 用 WGC 窗口采集，所有效果都关闭。
- “跨卡”指在设置里让 Veyra 用 AMD 核显运算，而画面在 5070 的显示器上。这和反馈人“显示器不接在处理卡上”是同一种接法。

| 情形 | 处理显卡 | 窗口 | 每秒收到/处理 | 提交 fps | 回调→Present P95 | gpuReady P95 |
|---|---|---|---|---|---|---|
| 同卡 | RTX 5070 | 962x572 | 60–61 | 60 | 1.67 ms | 0.74 ms |
| 跨卡 | AMD 核显 | 962x572 | 60–61 | 60 | 2.70 ms | 1.70 ms |
| 同卡 | RTX 5070 | 2562x1432 | 60–61 | 60 | 1.83 ms | 0.69 ms |
| 跨卡 | AMD 核显 | 2562x1432 | 60–61 | 60 | 14.27 ms | 13.30 ms |
| 同卡（本次构建） | RTX 5070 | 962x572 | 60–61 | 60 | 1.23 ms | 0.66 ms |
| 跨卡（本次构建） | AMD 核显 | 962x572 | 60–61 | 60 | 2.09 ms | 1.65 ms |

表中 P95 取逐秒统计的中位数。

结论：

- 关闭 NR 时，两种接法都稳定 60 帧，跨卡只增加延迟。采集画面和显示画面都要由 Windows 在两块显卡之间复制；核显较慢，所以 1440p 下延迟达到约 13 ms。
- 反馈里“关 NR 只有 50 多”在本机没有复现。本机没有第二块 NVIDIA，也没有 60 Hz 显示器，这两点都没能验证。

以下推断都没有得到证实：

1. **关 NR 只有 50 多帧**，可能有两种原因。
   - 游戏窗口所在的显示器是 60 Hz，游戏又没开垂直同步。WGC 每次刷新只能拿到最新的一张，相位抖动时 DWM 自己就会丢掉一些帧，这发生在 Veyra 之前。
   - 显示器接在游戏卡上，Veyra 却在副卡上运算，每帧要在两块卡之间来回复制两次。
2. **开 NR 只有 30 多帧**：一层 NR 在反馈人的分辨率和模型下，单帧耗时超过 16.7 ms 时，帧率就由 GPU 吞吐决定。功耗没满不能说明 GPU 有空闲，因为推理主要跑在张量核心上。

### 改动

- **找出驱动显示器的显卡**：新增 `displayAdapterLuid()`，从 Windows 显示路径（QueryDisplayConfig 的源适配器 LUID）查出驱动某块显示器的显卡。采集目标列表的每一项都带上 `displayAdapter`；窗口按它所在的显示器算，每块显示器只查一次。
- **日志**：采集打开时，以及目标移到另一块显卡的显示器上时，记一行 `[screen] gpu path display adapter=… processing adapter=… crossGpu=…`。跨卡时这行是 WARN，并说明代价。只在显示器变化时查询（约 0.1 ms），帧路径不变。
- **屏幕捕获对话框**：所选目标的显示器不接在 Veyra 运算的显卡上时，“捕获目标”下面会提示：
  - 两块显卡的名字；
  - 每帧跨卡复制会增加延迟；
  - 建议双显卡分工时把显示器接到处理用的显卡上（笔记本可以开独显直连）。

  新增四语词条 1 条。
- **测试**：`veyra_screen_capture_tests` 新增 3 项：
  - 每块显示器都给出驱动它的显卡，并且和 DXGI 列出它的显卡一致；
  - 窗口目标给出它所在显示器的显卡；
  - 空句柄返回 0。

没有改动的部分：

- 默认运算显卡：仍按 Windows 的高性能顺序，或用用户在设置里选的显卡。
- 采集、处理、显示的帧路径，以及所有默认值。

没有做“采集和显示留在 A 卡，只把 NR 放到 B 卡”的拆分管线。原因是 Windows 已经在做同样的跨卡复制，而拆分要新增跨卡共享堆和两套设备；本机没有第二块 NVIDIA，收益没法验证。

### Issue 里的建议与现状

| 建议 | 现状 |
|---|---|
| NR 期间保持原帧率 / 异步 NR | 已有“NR 自动推理复用”（专业页 NR 画面增强里，默认关闭）：跟不上时按光流复用上一次推理，最多每 2 帧复用 1 帧。限英伟达 NR、SDR、NR 运动用光流、列表模式。另有每层处理比例和性能模型可以降低单帧耗时。 |
| 多显卡 | 在设置的“GPU 占用监控”里选显卡，再打开“同时用这块显卡运算”。本次加上了跨卡提示和日志。 |
| 同步与跨卡传输 | 本次让跨卡情况可以看到。推荐接法：显示器接到处理卡上，和双显卡补帧软件的常见接法相同。 |
| NR 之后补帧 | 已有，DLSS、VFG、FSR 等补帧都在增强效果之后。 |
| 60 Hz 输出和采集不同步 | PR #108 的 G-SYNC 配置按钮可以让 Veyra 的窗口走可变刷新。 |
