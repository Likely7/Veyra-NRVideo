# 3b：自动 NR 档位的正常负载验证（2026-10-05）

## 前提与取舍

用户明确不再做压力测试。本节点只用正常 M1 1080p30 与既有作者生成的 M10 1080p60、正常可选 NR 配置及功能/画质回归，不启动竞争负载，不制造显存压力。M10 是合成运动，不冒充真实游戏或采集卡。

E1 已证明最大实例动态子区域与按实际尺寸创建的 NR 不等价；2b 的后台 Create 又显著扩大呈现断档。不能直接采用原方案这两条捷径。首先验证单个共享 snippet 会话内预建实际尺寸实例、帧边界切换的可行性。

## 有界候选

- 先做隔离测试接点，未验证前不接入默认产品配置或 UI。基于现有 NrInstance、类型化 NGX 参数与逐层 descriptor，不新建第二个 adapter/IAT owner。
- 一层 NR 的五个尺寸 100/85/70/55/40%，参考上限 1920×1080，实际 1920×1080、1632×918、1344×756、1056×594、768×432。其他层保持用户设置；最多一个自动层，加其他最多三层，共不超过既有已验证的八个 NR handles。更小输入、AMD、其他运行库、HDR、时域、节点复杂顺序和 FG 在扩大验收前保持原路径。
- 一次建好有界池；计入创建时间和全部显存，检查真实 WDDM budget，不能只报告切换快而隐去启动代价。保持源/输出/光流资源和尺寸不变；按当前自动档适配 guidance，仅 NR 的内部处理尺寸改变。切档排空已提交使用、重绑 views、reset 全部相关历史，不能回收尚在呈现的输出。
- 使用每帧增强区间的真实 P95，预算按源 transport 帧率 ×0.8（1a/1b 已拒绝，不能借“重复内容”虚增预算）。半秒观察，超预算降一档，连续3秒低于0.7预算才升档，滚动一分钟最多四次；开/seek/配置/暂停恢复后清空观察。若某档无法达到预算，如实保持最低档与欠速诊断，不谎报达标。
- 导出继续原生处理，不使用自动池。不强制改变已有 NR 层数、顺序、参数或固定档位，不恢复内置预设。

## 验收与保留门槛

1. 原生 debug 层：逐档实际 create / evaluate / 往返切换，与同一光流合同、实际尺寸独立创建的参考逐帧全 RGBA/PTS 比对；记录 reset、尺寸、句柄/参数清理、SDK 返回值和设备状态。
2. 普通播放匹配对照：基线/B/B-off 同一素材与配置，三次交错；观测 NR/增强 P95、呈现间隔/跳帧、切换间隙、池创建时间及显存。不得将局部 NR 的降低宣称为整体流畅度修复。
3. 若基本池的正确性、切换或资源代价不成立，归档并回退，记录反例；否则才接“自动（按负载）”、持久化/灰态/状态行，并补真实 UI 与导出边界回归。
