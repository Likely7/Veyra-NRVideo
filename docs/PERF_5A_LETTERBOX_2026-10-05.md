# 5a：黑边候选、画面合同与反例（2026-10-05）

只做普通负载和功能/画质实验，不做压力测试。开工存档`checkpoint/perf-nr-5a-letterbox-before-20261004`，源码`54fd585`。没有真实M3电影/M4主机采集，作者生成的图像/片段必须单独标记，不冒充电影或主机验收。

原方案“裁掉后直接填黑”不能原样进产品：已确认黑边后才出现的烧录字幕、台标和提示也属于用户画面。60帧确认/一秒滞回会让这类内容在发现前被抹掉；输出至少必须保留当前源在ROI外的像素。黑场和淡入不改变已确认范围，但恢复全画幅时不能沿用裁剪范围误伤新画面。

先用独立诊断验证两个问题：

1. 保守标准比例检测与确认/滞回，在全画幅、纯黑、淡入、窄暗边、标准黑边、后出现的字幕和比例切换上，是否会误伤；把预测区域与作者定义的实际有效内容逐帧核对。CPU参考只用于诊断，不能将全帧CPU扫描接入正常播放。
2. 实际ROI尺寸创建的现有NR图与完整尺寸NR相比，比较完整RGBA、有效区域PSNR/SSIM、边界/字幕原图和真实GPU增强区间。ROI外保留当前源，图内指引尺寸与像素单位遵循现有合同；这是独立画质/成本实验，不宣称生产GPU裁剪已接入。

若ROI尺寸改变产生不接受的边缘/时域变化，或检测无法满足原方案“不误伤”，记录反例、归档并不接默认黑边开关。只有ROI合同与正确性有证据才推进异步GPU小统计、生产资源重建、SR/光流/保护映射和UI；不能用理论25%像素减少作为提速结果。
