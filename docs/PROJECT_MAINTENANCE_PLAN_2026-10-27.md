## 六、按这个顺序执行

### 第 0 步：建立可恢复清单

1. 保存 refs、worktree HEAD/status、卷空间、在用进程、当前正式包 SHA。当前只读盘点已完成。
2. 处理脏树前保存原始字节、index 和 worktree patch、未跟踪文件；不要只备份已提交的 Git 历史。唯一模型/输入媒体和忽略脚本也要单列。
3. 需要移除分支前使用一份 bundle 并执行 verify，验证能恢复指定 tip；不再每个任务完整复制整个仓库，也不为每个旧分支额外创建一个新 checkpoint。

### 第 1 步：先收回可重建的大副本

- **34 套旧 CMake 构建**：候选文件 ID 对应 11.14 GiB；其中当前仅靠该组链接保存的分配量约 **11.14 GiB**。先保留构建参数/必要 EXE/唯一脚本与证据，再清可重建内容。
- **7 组被 2.1.1 替代的测试包**：候选文件 ID 对应 9.02 GiB；其中当前仅靠该组链接保存的分配量约 **7.27 GiB**。先保留构建参数/必要 EXE/唯一脚本与证据，再清可重建内容。
- **2 组解压验证副本**：候选文件 ID 对应 4.03 GiB；其中当前仅靠该组链接保存的分配量约 **4.03 GiB**。先保留构建参数/必要 EXE/唯一脚本与证据，再清可重建内容。

上述三组合并后，所有链接都在候选范围内的文件分配量为 **22.45 GiB**。这是保存必要资料之前的候选测算，实际回收要扣除保留资料、必要归档等成本，并以执行后卷空间为准。完整目录清单在 `candidate-scope-estimates.json` 和 `CLEANUP_PLAN.json`，不是“目录名匹配就全部删”。

当前正式版 staging 先保留，直到选定唯一 NVIDIA/AMD 运行供体并核对正式归档 SHA；然后才能清掉 staging 中重复 ZIP/源码与多余运行副本。2.0.7–2.1.1 的正式 ZIP/对应源码不动。

### 第 2 步：收拢分支与工作树

- 先归档并移除干净、已合入 main 的旧工作树；检查所有 ignored 文件，尤其任务脚本与 runtime 原件；使用 `git worktree remove`，不强制绕过脏状态。把历史构建引用和脚本入口先移出这些旧树。
- 已合分支在清单和 Git 历史可恢复后退出日常分支列表。main 保留；Lecram 两条暂停线保留；尚有独有文档/研究的分支先入档。
- 远端分支与现有发行标签另列清单；当前方案不包含远端删除、强推、重写历史或 `gc --prune=now`。
- 日常只保留 main 与少量正在做的任务。暂停工作放入明确的暂停清单，已交付任务关闭，不长期保留一套完整工程和完整运行包。

### 第 3 步：让文档有一个现在，而不是几百个现在

- `AGENTS.md` 只保留当前有效规则、依赖根、产物路径、权限/许可与当前入口；逐日授权原文移到带日期的历史记录，保持可追溯。
- `docs/CURRENT_STATUS.md` 只记录当前正式版、当前开发基线、活动工作、暂停项、已知问题和验收边界，历史交付转索引。不要用旧“未合 main”覆盖今天的事实。
- `docs/WORKLOG.md` 按月份或版本归档，首页只保留当前记录和链接；历史 PLAN/REPORT 通过索引查，不要求每个 Agent 逐篇读。
- `codex/doc-cleanup-vram-amd-20261020` 的文档纠偏按当前事实人工折叠，不能整分支覆盖当前文档。移动文档后扫描相对链接和脚本硬编码，保留必要入口桥接。

### 第 4 步：单独处理代码维护成本

- 先为 QmlPlayerBridge 按“片源与播放 / 增强设置 / 字幕与音频 / 导出与录制 / 设备状态”拆职责；然后拆 ProPage/DialogHost 的页面和对话框。每次一个边界，保留现有接口与配置格式。
- 旧 Win32 界面还被 CMake 和部分字幕/测试目标引用，不能因为当前主界面是 QML 就直接删除 apps/veyra。先查依赖与实际构建目标，再迁移共用代码、做独立删除变更。
- 整理 scripts/acceptance：正式回归入口集中维护，历史任务脚本入档；当前 610 个 scripts 文件不能简单按日期删除。
- 每次拆分都先构建和做相应回归；采集/音频/补帧/颜色属于行为敏感链路，避免和磁盘卫生混在一个大变更里。

## 七、收尾与预防再次膨胀

1. 依赖只留有身份清单的共享原件；C:/veyra-deps Junction 保留；patched FFmpeg 与对应源码、许可证保留。
2. 一个任务一份可用运行目录、不同用例使用不同 data-dir/log/TEMP；只有需要修改运行内容的故障注入才额外复制，结束即回收。
3. 已发布资产只有 releases 下的正式归档为长期入口；test-packages 和 verify 不再长期重复保留。
4. 每次交付记录“当前分支 / 是否合 main / 保留的构建与运行供体 / 可清理目录 / 新增与回收空间 / 未验边界”。
