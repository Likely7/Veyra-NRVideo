## 为什么删掉 RIFE

- **用户实测**：4K 30 fps 下 RIFE 2X 每对帧预计 35–40 ms，超过 33 ms 预算，部分帧对被拒绝。
- **本机补测**：导出串行、每个源帧多出的时间如下。

  | 补帧 | 1080p | 4K |
  |---|---|---|
  | VFG 中 | +2.2 ms | +6.6 ms |
  | VFG 高 | +15.1 ms | +13.2 ms |
  | RIFE | +9.0 ms | +32.1 ms |

- **画质**：对 60 fps 真值，RIFE 25.08 dB，VFG 中 25.36 dB，RIFE 不占优。
- **适用面**：RIFE 原本只对没有 VFG 的 30 系有意义；30 系 VFG 兼容由 Codex 在 `codex/vfg-ampere-20261102`（`edad6e9`）上完成。**它不在 main，也不在本分支**；两边都改了 `EffectAvailability.h`、`Hardware.cpp`、`i18n/catalog.json`，合并时要注意（`ampere` 字段和“GeForce RTX 30”判断已与该分支写成一样）。
- **代码处理**：RIFE 的全部代码已删除：worker、协议、后端、着色器、`PairFrameGenerator` 接口、补帧后端值 5、界面、节点、预设和翻译。补帧相关文件全部回到 main 原样，VfgBackend 也未改动。
- **下载和依赖保留在本机，没有删除**（约 1.6 GB）：
  - `downloads/claude-vsr-rife-20261105`（1.1 GB）；
  - `deps/claude-vsr-rife-20261105`（241 MB）；
  - `build/claude-vsr-rife-20261105/bench`（247 MB，基准程序）。

  是否删除由用户决定。测试程序里的 RIFE 运行组件（343 MB 副本）已删除。

## 用户能看到的变化

- **“超分算法”下拉**改为：DLSS SR、RTX 视频超分 · 标准、RTX 视频超分 · 高码率、RTX 视频超分 · 流媒体、FSR。
- **“档位”**（原“质量 1/2/3/4”）改为“低 / 中 / 高 / 超高”。
  - 流媒体只有中和超高两档：SDK 只有 21 和 23 两个模式。
  - 在三个版本之间切换时保留档位；从流媒体以外切到流媒体时，低/中对应中，高/超高对应超高。
- **双重超分**三个版本都能开。
  - 第二次超分有自己的“第二次超分算法”（三个版本可选，可与基础不同）和“第二次超分档位”。
  - 任意组合都能跑，例如流媒体先清理压缩痕迹，再用高码率保留细节。
- **“超分后缩回到”**（超采样）三个版本也都能用。
- **卡片摘要**示例：“RTX 视频超分 · 流媒体 · 4K→1080p→4K · 中 / 高码率 超高”。
- **高码率和流媒体只做放大**：片源已经达到目标尺寸时不运行，超分区下方会提示“同尺寸修复请用标准”。只有标准版本会做同尺寸修复。
- **可用性**：标准需要 RTX；高码率需要 RTX 加 Video Effects 运行组件；流媒体还要求 RTX 30 及更新。

## 设计

- **存储值不变**，沿用 SDK 编号：标准 1–4，高码率 16–19，流媒体 21/23，DLSS 0，FSR 5。
  - 新增 `VideoSrFamily` 及 `videoSrFamily / videoSrTier / videoSrQualityFor / rtxVideoSr / ngxVideoSr`。
  - 原 `srStageBackend` 只表示标准，改名 `ngxVideoSr`。双重、超采样、先降的判断改用 `rtxVideoSr`（三个版本）。
- **界面桥接**新增 `srAlgorithmOf / srTierOf / srQualityFor / srTierChoices / srQualityLabel`。
  - 算法 id：`rtx` / `rtx-hb` / `rtx-st`，DLSS 和 FSR 仍用数字。
  - 列表、节点和保存预设的摘要共用这些函数。
- **每一次超分各自选运行库**：
  - 最终一次用 `dualSrQuality`（双重时）或 `videoSrQuality`；第一次（仅双重）用 `videoSrQuality`。
  - 标准走 NGX；高码率和流媒体各自是一个 `VfxSrBackend` 实例。
  - 只有用到标准时才创建 NGX。
  - 两个 NGX 实例共用创建键时，沿用原来的复用规则。
- **Video Effects 交接**：拷入 → 提交 → 队列信号 → CUDA 运行 → 队列等待 → 在同一槽的下一个命令列表拷出，图的队列上没有 CPU 等待。
  - CUDA 流必须是阻塞流：VideoSuperRes 有一部分工作排在旧式默认流上；非阻塞流会读到旧输入、输出错帧。第一轮已修复，见下。
- **双重时第一次为 Video Effects 但不放大**（片源已达到基础目标）：第一次结果直接复制片源。日志记为 `firstRuntime=copy`。
- **显存准入**：
  - 计入 Video Effects 每次超分的共享输入、输出缓冲；
  - 双重或超采样时，每个已加载模型预留 256 MiB（NGX 共用一份，每个 Video Effects 实例一份）。这是估算，不是测得的 SDK 峰值。
- **设置可用性检查**也覆盖第二次超分的版本。

## 持久化

- **设置预设**（PresetStore）：基础或第二次超分用到 16–23 时写 v35，否则保持原版本（标准双重仍是 v34）。
- **预设库**（v18）和**模式会话**（v13）：用到 16–23 时写到 `.video-ai` 附属文件，旧文件字节不变，旧版本读到的仍是旧文件。
- **导出 worker 协议未改**：新值不改变字段布局。
