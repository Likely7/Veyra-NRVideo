# 超采样选项：超分后缩回（2026-10-28）
> ⚠️ 路径提示：文中 `E:/项目/Veyra/...` 是迁移前的记录（现为 `D:\Program\Veyra`），按日期理解；当前入口见 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 用户合同

用户看过双重超分复查的图片A/B后，选择把“先超到更高分辨率，再精确缩回输出尺寸”做成基础超分的选项。在施工树`codex/dual-sr-20261028`完成，用户随后要求直接合并到本地main（提交与合并哈希见FINAL回执）；未push、未Release，不改真实配置、SDK、模型、驱动，Lecram暂停。双重超分保留，默认关闭。

依据见[双重超分复查](DUAL_SR_PLAN_2026-10-28.md)的“复查修正”和“追加对比”：在两帧GTA VI原生4K上，双重超分所有组都不如单次；先超到8K再缩回4K四组都比单次更接近原图，只多约1–3ms。

## 行为

- 列表与节点共用`SrStageEditor`，在“质量”下新增“超分后缩回到”：不缩回 / 片源尺寸 / 2K / 4K / 5K / 6K / 7K，默认不缩回。“目标尺寸”此时是超采样的中间尺寸。
- 只在单次RTX视频超分（质量1–4、NVIDIA）生效。双重开启时该行禁用但保留选择，关闭双重后恢复；DLSS SR、FSR、其他显卡保持原单次路径。
- 链路：源 → RTX视频超分到目标尺寸 → 线性光精确面积缩回（HDR先按纹素恢复再平均）→ 降噪、补帧、调色、显示都按缩回后的尺寸运行，不在8K上跑。
- 超分没有放大或缩回尺寸不小于超分结果时不缩回，实际尺寸下方说明原因。运行中显示`1920x1080 → 7680x4320 → 3840x2160`；卡片摘要如“RTX 视频超分 · 8K→4K · 质量 1”。
- 图片、视频文件、采集与导出共用同一尺寸合同。

## 实现

- 字段沿用`srOutput`。PresetStore v33+、PresetLibrary v16+、ChainSession v11+已保存它，无格式升级；旧单层预设里设过“再缩到”的，现在按超采样生效。
- `runningSrOutput`恢复返回`srOutput`（仅上述条件）；`activeVideoSettings`只在单次RTX视频超分时保留它，所以双重开启或其他后端下修改它不重建图；执行计划同样传入。GPU复用原有的`SrResolve`缩回pass。
- 导出worker共享布局不变，但该字段语义变了，协议13→14，避免旧worker静默忽略缩回。
- 显存：超采样图与双重图一样走WDDM预算准入，纹理估算加上超分结果RGBA8，SDK预留（RTX 256MiB、NR启用1GiB、VFG每工作像素128B），再留可用预算20%；不足则拒绝事务，不改请求尺寸。普通单次路径保持原规则。预留是保守估算，不是SDK峰值测量。
- 日志改为`supersample evaluate=WxH output=WxH`与`dual reduce=…`，不再写“three-step”；相关注释同步。
