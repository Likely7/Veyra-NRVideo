## 0. 一句话结论

用户提出的顺序是：先做浏览器原型，再改造链路，最后迁移 UI。这个方向是对的，建议做三处调整：

1. **最前面加一个 1–2 天的 Qt 窗口探针。** 先确认 Qt 窗口能不能稳定托管现有视频窗口；如果不行，后面所有 QML 设计都要改，所以最先验证。
2. **链路改造分两步。** 第一步只加“效果链数据模型 + 效果注册表”，输出与现在逐像素一致；第二步才拆分执行器、放开顺序和 NR 叠层。第一步风险低，而新 UI 必须以它为基础。
3. **节点模式最后做，并先限定为“单链路自由排序”。** 分支、混合等真正的有向图（DAG）放到以后。

原因：极简和专业（列表）两个页面不依赖节点能力，可以先迁到 QML 并交付；节点模式需要引擎支持可变顺序，风险最大，放最后，不拖累前面。

### 1.2 Magpie（SAOG0721 实验分支）

查看的提交：分支 `experimental` 最新提交 `3841698348bfb246623d4acf791984c8b68a577b`；上游 `Blinue/Magpie` 为 `69d6105d56a74d9160716adb4359c3f80909f971`。两者都是 GPLv3。

- **数据模型**：一个“缩放模式”就是一串有序效果，每个效果记录 `{名称, 参数表(float), 缩放方式(Normal/Fit/Absolute/Fill), 缩放值}`，全部存在 `config.json` 里。
- **严格线性链**：`Renderer::_BuildEffects()` 把一张纹理依次穿过所有效果。单个 `.hlsl` 内部可以有多 pass、多输入，但效果和效果之间不能分支或混合。**Magpie 没有节点编辑器。**
- **参数元数据**：参数在效果文件里用 `//!PARAMETER`、`LABEL`、`DEFAULT`、`MIN`、`MAX`、`STEP` 声明，UI 据此自动生成。该分支还加了：
  - `//!GROUP` 分组、`//!OPTION` 下拉选项；
  - 按条件显示或隐藏参数的规则（`EffectParameterRules.h`）；
  - “改了需重启才生效”的参数队列（`EffectParameterRestart.h`）。
- **交互**：按分类搜索的“添加效果”选择器；每个效果一张卡片，参数放在弹出面板里；自绘拖动手柄排序（不是上下按钮）；可在工具栏实时调参，双击滑条复位。
- **该分支新增的效果**：`DLSSNR_AI_Filter` 最多 3 次串行 pass，可配残差、防闪、光流（None/AMDOF/NVOF）；另有 DLSS SR/FG、XeSS FG、FSR2/3/4 和 RTX Video 的 VSR/降噪/HDR。
- **UI 技术**：UWP XAML（WinUI 2，XAML Islands）加 C++/WinRT。**界面代码无法直接移植到 QML。**

**可以搬的**：
- 效果“注册表 + 参数元数据”的思路；
- 条件显示和“实时 / 需重建”的参数标注；
- 分类搜索式添加效果；
- 线性链的 JSON 存储格式；
- DLSSNR 多次串行 pass 的实现方式（作为 NR 叠层的技术参考）。

按项目规则，移植代码要记录来源仓库、固定提交、许可证和改动，写入 `THIRD_PARTY_NOTICES.md`。

**需要自己做的**：节点画布本身，以及 Veyra 的 D3D12 执行器。Magpie 走 D3D11，NGX 接法也不同。

### 1.3 Qt 相关能力（官方文档）

- **`WindowContainer`（Qt 6.7+）**：可以把外部原生窗口（`QWindow::fromWinId`）放进 QML 场景，并同步位置、尺寸、可见性和裁剪。官方明确说明：被嵌入的窗口**永远盖在 QML 场景之上**，同级或子级 Item 都无法盖住它，要盖住只能再开一个子窗口。
  [文档](https://doc.qt.io/qt-6/qml-qtquick-windowcontainer.html) ·
  [Window embedding 博客](https://www.qt.io/blog/window-embedding-in-qt-quick) ·
  [示例](https://doc.qt.io/qt-6/qtdoc-demos-windowembedding-example.html)
- **`Popup.popupType: Popup.Window`（Qt 6.8+）**：菜单、提示、下拉可以作为独立顶层窗口显示，外观仍由 QML 绘制，所以能浮在视频窗口上方。
  [文档](https://doc.qt.io/qt-6/qml-qtquick-controls-popup.html) ·
  [博客](https://www.qt.io/blog/popups-and-menus-in-qt-quick-6.8)
- **QuickQanava**：Qt6/QML 节点图库，BSD-3 许可（与 GPLv3 兼容），最低 Qt 6.5。
  [仓库](https://github.com/cneben/QuickQanava)

**由此得出的版本要求**：至少 Qt 6.8。具体版本在探针阶段按当时的 LTS 固定。

## 2. 整体视觉方向

### 2.1 基调

- **背景**：取消 DWM 亚克力和半透明玻璃，改为深黑带极轻渐变。例如从左上 `#101014` 径向过渡到 `#08080A`，亮度差控制在 3–4%。
  - **必须加极轻噪点或抖动**：8 位显示上的暗部渐变很容易出现色带。
- **层级**：统一用“卡片”：
  - 底色 `#16161A`，1 px 描边 `rgba(255,255,255,0.06)`，圆角 16–20 px；
  - 悬停时提亮描边；选中时描边用强调色；
  - 不用大面积模糊。
- **文字**：只用三级透明度，即主文字 92%、次要 60%、禁用或提示 38%。
  - 字号收敛为 12 / 13 / 15 / 20 / 28 五档；
  - 数字用等宽数字（tabular figures），避免读数跳动。
- **字体**：随包附带开源字体（如 Noto Sans SC / 思源黑体 + Inter，均为 OFL），不依赖系统里有没有“微软雅黑”。
- **强调色**：保留现在的橙色作唯一强调色；另有语义色：成功绿、警告黄、错误红、实验紫。节点端口按数据类型着色：SDR 画面白、HDR 画面琥珀、光流蓝。
- **图标**：继续用现有 Lucide（ISC 许可），统一 1.5 px 线宽。
- **Logo**：新像素手柄 Logo 用于启动动画和侧栏顶部。**问题**：现在的 `新logo.png` 是 1536×1024、黑底、1.2 MB 的位图。需要一份透明底的矢量版（SVG）或至少透明 PNG，否则侧栏小尺寸会糊，光晕也会带出黑底。

## 3. 三页面与切换

### 3.1 导航骨架

```text
┌──┬──────────────────────────────────────────────┐
│◉ │                                              │
│  │                                              │
│▶ │   当前页面内容（极简 / 专业 / 导出）          │
│⚙︎ │                                              │
│⇪ │                                              │
│  │                                              │
│──│                                              │
│♡ │                                              │
│⋯ │                                              │
└──┴──────────────────────────────────────────────┘
 56px 黑色图标栏
```

- **图标栏**（56 px，纯黑，参考 `侧边栏.jpg`）：
  - 顶部依次是 Logo、**观影（极简）**、**专业**、**导出**；
  - 底部依次是 **设置**（全局偏好、组件页、关于）、**支持**（交流群 / 赞助 / 反馈）、**诊断**。
- **全屏**：图标栏隐藏，只保留全屏控制条。
- **页面切换**：图标栏的选中指示块用弹性位移动画滑到新图标；内容区做“共享元素”过渡：
  - 视频区原地缩放到新位置，而不是淡出再淡入；
  - 右侧面板和底部卡片带弹性滑入，卡片之间错开 30–40 ms 依次出现。
- **切换规则**：沿用现有约定，切换页面不重开源、不提交设置、不改 revision。

**为什么不用顶部标签页**：以后功能会越来越多，竖栏能放下更多入口且不挤占视频宽度，也和参考图一致。

**关于命名**：代码里叫 Daily，界面上改叫“极简”，内部枚举同步改名，避免文档和代码对不上。

### 3.2 片源入口（三页共享）

“打开文件 / 采集卡 / PS5 / 屏幕捕获”是**片源**，和“极简 / 专业 / 导出”这三个**工作区**是两件事，不放进图标栏。

- **极简页**：放在空状态和底栏的“片源”按钮里。
- **专业页**：放在左上片源卡里。
- **导出页**：放在“选择输入”里。
- 三处调用同一个片源面板组件，不写三份。

- **画质胶囊**：一键档位 `关 / 流畅 / 均衡 / 极致 / 我的预设…`。档位只是切换预设，背后仍是同一条效果链，和专业模式互通。
- **补帧胶囊**：`关 / 2X / 3X / 4X…`，只列当前显卡实际可用的倍率。
- **状态点**：胶囊左侧的小圆点表示状态：绿 = 已生效，黄 = 应用中，红 = 失败已回滚（悬停显示原因）。替代现在一整行的技术文字。
- **性能小环**：侧边可选一个“流体凹槽”标签，内含 2–3 个环，参考 `性能图标.jpg`，默认折叠。
  - 可显示：GPU 占用、增强耗时占帧预算百分比、软件提交帧率 / 目标。
  - 每个环必须写明测的是什么，不能把“软件提交 FPS”写成屏幕刷新率。
- **播放条交互**：
  - 播放 / 暂停图标做形变动画；
  - 进度条悬停时加粗并显示预览；
  - 音量滑条回弹；
  - 按钮点击有 0.96 的按压缩放。

### 4.3 全屏

保留自动隐藏和 Ctrl+L 锁定。控制条外观与窗口模式统一。它必须是盖在视频上的独立窗口，技术路线见 §7-1。

**画布交互**：

- 滚轮缩放，中键或空格拖动平移，框选；
- 右键打开分类搜索菜单来添加效果（参考 Magpie 的效果选择器）；
- 从端口拖线连接；
- 把节点拖到已有连线上会自动插入；
- 双击节点展开内嵌参数；
- 常用参数直接在节点卡内调（像 `节点参考 (2).jpg`），完整参数在右侧检查器。

**动画**：新节点弹性落位；连线以流光动画示意“数据方向”，**仅在编辑时播放，播放视频时静止**，避免持续消耗 GPU。

**固定节点**：输入节点在左、输出节点在右，都不可删除。补帧放在输出前的专用槽位，不能放到中间（原因见 §6.3）。

**视频放在哪里**是节点视图最大的设计问题，见 §7-4。建议右侧停靠一个固定的“预览”面板显示真实播放画面，下方是选中节点的检查器；预览面板可以用分隔条调整大小，也可以弹出为独立窗口。

**第一版只允许单链路**：从输入到输出只有一条路径，可以任意排序、插入、删除、旁路（bypass）。不允许分支和两路混合；UI 给出提示“混合节点以后支持”。

- **原因**：单链路可以无损地映射回列表视图，两种视图始终编辑同一份数据；分支需要执行器支持多输入，GPU 开销也会成倍增加。
- **非法连接**：连线变红，并说明原因，例如“补帧必须是最后一步”“HDR 输出后不能再接仅支持 SDR 的效果”。

**两种视图的关系**：列表视图和节点视图是同一份 `EffectChain` 的两种显示方式。节点坐标另存为“布局元数据”，拖动节点不提交设置、不增加 revision。

## 6. 链路改造（为节点模式和叠层打基础）

原则：解码、音频、采集、PS5、Present、帧同步、导出编码这些链路都不动。只改 `EnhanceGraph` 内部“效果如何被描述和串起来”。每一步都要能与改造前的输出做逐像素对比。

### 6.1 第一步：效果链数据模型 + 效果注册表（不改变行为）

- **`EffectChain`**：一个有序的 `EffectInstance` 列表，每项包含 `{instanceId, typeId, enabled, 参数(按类型), 版本}`；另有全局项，如处理尺寸策略、HDR 输出。
- **`EffectRegistry`**：每种效果注册以下元数据（参考 Magpie 的元数据做法）：
  - 名称、分类、图标；
  - 参数表：类型、最小 / 最大 / 步进 / 默认、分组、选项、显示条件；
  - 每个参数属于“实时生效”还是“需要重建”；
  - 输入输出能力：SDR/HDR、是否改变分辨率、是否需要光流 / 历史帧；
  - 位置约束：必须在最后、每条链最多一个、与谁互斥；
  - 硬件要求：RTX 30/40/50、AMD、Intel。
- **双向转换**：`EffectChain` 与现有 `EnhancementSettings` 互相转换。测试要求所有现有预设（含 v20 mode 6 迁移）“转过去再转回来”完全一致。
- **自动推导重建条件**：`EngineController` 的重建判断改为由注册表推导，替换 `:855` 附近的手写列表。旧列表保留作对照测试，对齐后再删。
- **存储**：新增 JSON 预设格式（`veyra.chain` schema v1），保留 `VEYRA_PRESETS` v21 的读取和迁移。节点布局单独存。
- **收益**：以后新增效果只需“注册元数据 + 实现 pass”，列表视图、节点检查器、预设存储和重建判断全部自动跟上，UI 不再每次手写一堆控件。这正是现在 UI 越改越乱的根因。

### 6.2 第二步：执行器拆分

- **拆 pass**：把 `EnhanceGraph` 里写死的各个 pass 拆成独立的 `IEffectPass`，统一接口为 `create(尺寸, 格式)`、`execute(命令列表, 输入, 输出, 帧上下文)`、`reset()` 和 GPU 计时。
- **初期不改顺序**：执行器先严格按现有固定顺序组装。与改造前对比输出像素、每个 pass 的 GPU 时间、reset 行为和日志，必须一致或在记录的误差内。
- **再开放顺序**：通过校验后，才允许按 `EffectChain` 的顺序执行，非法顺序在提交阶段直接拒绝并回滚。
- **色彩独立**：色彩 / LUT 目前合并在导入着色器里。只有当用户把色彩节点移出开头位置时，才需要独立 pass；默认位置继续走合并路径，性能不变。
- **不变的规则**：reset 规则（seek、换源、resize、scene cut 等清空全部历史）改为对链上每个实例逐个执行；导出继续冻结一份链快照。

### 6.3 顺序约束（节点模式也必须遵守）

- **补帧（DLSSG / XeSS FG / FSR FG）固定在最后**：XeSS / FSR FG 本来就在 Present Sink 里，OSD 和字幕在补帧之后合成。这是 AGENTS 规定的边界，节点模式不能打破。
- **SR 与 NR 的两种顺序**已有实现（默认 / 低延迟），其他排列需要逐个验证画质和时域稳定性后才标记为“已验证”。
- **RTX Video HDR 之后**只允许接支持 HDR 的效果。
- **允许但未验证的组合**：节点模式可以放开，但要标“未验证”，不能宣称画质提升。

### 6.4 NR 叠层（单独的技术与画质探针）

这件事以前被暂缓过，建议 UI 设计照做，但**引擎能力先用探针确认**：

1. **能力**：同一个 `DlssNrRuntimeAdapter`（全局 IAT 钩子、单一占用标志）能否创建 2–4 个 NR feature 并逐个执行？如果不能，另一条路是像 Magpie 分支那样对同一个 feature 串行执行多次，但这样每层参数不能独立，只能部分满足需求。
2. **历史**：每层独立的时域历史、`kReset` 和防闪状态。
3. **成本**：每层的 GPU 时间和显存。1080p 内部处理下叠 2 层是否还能实时，4K 原生下是否可行。结果用来决定默认上限和实时 / 导出分别允许几层。
4. **画质**：叠层是否真的更好，还是会过锐、出油画感、闪烁。用同一素材做 1 / 2 / 3 层对比，由用户看效果决定是否公开这个功能。

探针不通过时：UI 保留“NR 层”结构但上限为 1，或只在导出中允许多层。

## 7. 问题与风险（用户需要知道的）

1. **QML 盖不住视频窗口。** 视频是 D3D12 直接画在一个原生子窗口上。Qt 官方说明嵌入的原生窗口总在 QML 之上，因此：
   - 视频上的半透明信息块、圆角遮罩、毛玻璃这类 `专业模式.jpg` 式的叠加效果，不能用普通 QML 实现；
   - 全屏控制条、字幕、右键菜单、下拉框都必须是独立的小窗口。菜单类可用 Qt 6.8 的 `Popup.Window`；全屏控制条要单独做一个透明 QML 窗口，或先保留原生的；
   - 专业页的视频圆角：要么接受直角（视频贴边，外框用卡片描边），要么在最终输出着色器里画圆角遮罩。后者会碰到 Present 路径，改动虽小，也要单独验收。**建议直角。**
2. **视频区尺寸动画。** 每次改变视频窗口大小都要清空 GPU 队列再 `ResizeBuffers`，会造成卡顿。动画过程中只移动 / 拉伸，结束时再做一次真实 resize，这是现有做法。“弹性动画”对视频区只能用短而克制的曲线，回弹不能让视频反复变大变小。
3. **UI 动画会和增强抢 GPU。** Qt Quick 只在画面变化时重绘，但长时间循环的发光、流光、呼吸动画会让它每帧都画。规则如下：
   - 播放时 UI 应静止；
   - 关键过渡用在渲染线程执行的 Animator；
   - 性能读数低频刷新；
   - 设置里提供“减少动画”；
   - 用同一素材对比 UI 动画开 / 关时的提交间隔和 GPU 时间。
4. **节点视图里视频放哪。** 把视频放进画布（例如输出节点里）意味着平移和缩放画布时要不停移动 / 改变视频窗口大小，还会被节点遮挡关系卡住；画缩略图则要 GPU→CPU 回读，这是正常播放路径的禁区。所以建议：固定的停靠预览面板 + 可弹出的独立预览窗口，画布只放节点。
5. **节点自由度越大，测试组合越多。** 每多一种可排序效果，组合数就成倍增加。单链路 + 约束 + “未验证”标注，是可控的范围；分支和混合要等执行器和测试跟上。
6. **改连线会触发重建。** 创建 NGX feature 可能要几百毫秒，画面会短暂停顿。参数分两类：
   - 实时参数：拖动时立即生效；
   - 结构变化（加删节点、改顺序）：松手后才提交，显示“应用中”，失败则整套回滚到上一条可用链。
7. **两个编辑器、一份数据。** 列表和节点必须编辑同一个 `EffectChain`；预设、极简页的画质档位、导出冻结设置也都基于它。不能出现“节点模式里一套、列表里另一套”。
8. **导出页独立后的边界。** 旧方案写过“导出期间仍能观看需要补齐工程”。本轮没有核对它当前是否已实现，做导出页前要先确认，不能用 UI 隐藏来冒充后台导出。
9. **全屏与 HDR、OBS、多显示器。** 换成 Qt 宿主后，这些都要重测：
   - 独立翻转资格；
   - HDR 输出状态；
   - OBS 窗口捕获层级；
   - 跨 DPI 拖动（U2 曾出过跨屏卡死）。
10. **体积、启动和许可。**
    - Qt Quick 运行库大约增加几十 MB（以实际 `windeployqt` 结果为准）。
    - QML 首次加载要编译，用 `qt_add_qml_module` 的预编译和缓存可以缓解。
    - Qt 各模块多为 LGPLv3 / GPL，与 Veyra 的 GPLv3 兼容，但要逐模块核对（尤其是特效类模块），动态链接，并写进 `THIRD_PARTY_NOTICES.md`；不能用只有商业许可的模块。
11. **测试体系要重建。** 现有 `veyra_ui_contract_tests`、`veyra_settings_layout_tests` 等是针对 Win32 的，需要改成：
    - Facade / 模型的 C++ 单元测试；
    - Qt Quick Test 页面测试；
    - 保留“UI 操作不触发重开、seek、revision、图重置”的自动检查。
12. **过渡期两套 UI。** 在 QML 版与旧版功能对等之前，保留旧 Win32 UI 作为构建选项和回退，不一次性删除。
13. **暗色渐变色带。** 见 §2.1，要加抖动，并在真机 8 位和 HDR 两种桌面下都看一眼。
14. **语言。** 从第一天起所有文字用 `qsTr`，以后做英文版不需要返工。
