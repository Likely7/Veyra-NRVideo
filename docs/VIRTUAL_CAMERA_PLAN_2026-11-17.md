## 实现合同

- 复用PresentCapture处理后全尺寸纹理入口，独立于窗口尺寸；默认关。标准DirectShow设备Veyra Virtual Camera，独立CLSID/共享内存名，兼容64/32位消费者，不借用或覆盖OBS设备。当前用户注册、卸载，仅操作本设备键；正常应用无管理员要求，不改驱动。
- 优先适配OBS Studio官方虚拟摄像机/共享队列/缩放代码，固定7e3aa99811798255bd1a13a6da7260ada76a4d95；libdshowcapture固定8878638324393815512f802640b0d5ce940161f1（LGPL-2.1-or-later），OBS部分GPL-2.0-or-later，保留来源/许可/修改清单。参考微软MFCreateVirtualCamera仅Build22000起；本轮采用OBS类DirectShow接口，不以此声称每个仅支持MF的应用均验证。
- 输出SDR NV12、BT.709 limited；HDR在输出边界GPU转SDR。GPU→CPU仅本功能打开时在独立兼容输出边界执行：GPU转换/有限3槽异步读回，播放线程不等待CPU fence/消费者；所有额外丢帧计数。不改正常播放/导出算法，不叠加编码器。
- 共享队列有界，处理分辨率与摄像机消费者协商分辨率分别记录。改变源/图/设备时正确释放旧代GPU资源并重连。停止/无输入不能无限输出旧画面；暂停保留当前帧，关闭输出黑帧。音频不冒充摄像机音频端点。
- 原生图内FG输出可采集；XeSS等SDK接管Present的生成帧不在当前PresentCapture图输出内，必须在界面/说明如实标注，不能宣称这些帧已输出。另检查最小化/无显示尺寸时是否仍出帧，不以普通窗口测试代替。
- Pro录制旁增加开关/状态；设置提供使用说明和卸载入口；四语同步。录制和即时回放原行为保持。

## 用户实测追加：管理员 OBS 的设备可见性

用户明确报告 OBS 视频采集设备列表缺少 Veyra。当前 HKCU 两架构注册与DLL原件仍存在，普通权限 FFmpeg 能枚举到摄像机；用户 OBS 32.1.2 的 2026-11-17 两份现场日志均为 Running as administrator: true。先前普通权限 OBS 33.0.1 的验收未覆盖此权限组合，不能替代它。

补齐可选的系统级组件安装/修复/卸载入口：独立静态CRT小程序，Windows runas 管理员确认，由用户处理系统授权界面；不自动确认或更改 UAC。模块放系统 Program Files 的 VeyraVirtualCamera/hash 版本目录，目录与文件由管理员/系统拥有并写入，普通用户仅RX；校验源DLL嵌入的构建SHA，不从可写便携目录注册系统COM、不修改OBS或其他摄像机。注册成功后在安装程序的管理员上下文实际枚举并绑定本设备，失败回滚本设备原注册。正常Veyra只保留原权限，摄像机组件安装后启用不重建HKCU覆盖。首次安装需管理员确认，此修订覆盖前文“无管理员要求”的普适承诺；普通权限的当前用户模式仍保留。

验证安装前先做不提升权限的载荷校验与拒绝写入检查；安装后分别查机器/用户键、组件ACL、管理员枚举/绑定证明、真实OBS设备和收帧。用户OBS与便携QA OBS、普通权限与管理员权限结果分别记录。证据：reports同任务CAMERA-MISSING-REGISTRY.json/CAMERA-MISSING-ENUM.log及后续安装回执。本次仍未授权合main/推送/Release。

## 用户实测追加：OBS流畅度与限帧容差

用户OBS32.1.2现场源已是60 FPS/NV12/关闭缓冲，不能用“设成60”解释全部症状。日志曾出现Veyra约119提交FPS但摄像机限60，之后60→30配图内2X为约60；OBS源还从3840×2160变为6144×3456，而画布/输出2560×1440。后者增加传输及缩放工作，但没有现场渲染/编码超载数据，不能据此断言显卡性能不足。

摄像机限帧原使用严格now<nextDue，略提前到达的新帧会跳过；沿用LiveRecorder已有的四分之一周期到达容差，保留原累计目标时刻与三槽上限，不加队列或渲染线程等待。真实GPU动态回归使用独立高精度定时器，59.94 Hz源带±0.75ms到达抖动：120张输入，旧逻辑接收/发布93，修复后120，独立NV12读者读取到初始帧加120张变化帧，D3D12调试错误0；这些是本机受控短测，不是用户OBS现场丢帧率。普通Sleep(1)首版夹具受Windows计时粒度影响，已记录并改正，不能将其读帧漏采当成产品传输丢帧。

实际产品另用动态1080p60文件→系统已注册DirectShow摄像机→FFmpeg读360帧，排除首尾各约0.5秒后299相邻对无逐像素完全重复，结果CADENCE-PRODUCT.json。该项不包含OBS、实卡、6K高负载或物理屏幕延迟；不据此承诺所有场景完全一致。设置建议优先4K最终处理输出/4K摄像机源/60 FPS三处匹配；需要减小节奏抖动时对照OBS缓冲自动/启用与关闭的延迟取舍，编码超载仅在实际统计确认后另查。

## OBS 捕获处理后画面

直播时可在 Veyra 的录制按钮旁启用「虚拟摄像机」。在 OBS 的来源里添加「视频采集设备」，选择「Veyra Virtual Camera」。画面取自 Veyra 的处理输出，Veyra 窗口可以保持窗口化。声音在 OBS 里单独选择现有的采集卡音频或 Veyra 使用的播放设备。
