## 原因

垂直同步下的丢帧分两种：

1. 时钟差造成的滑移，比如 59.944 fps 对 60.005 Hz，每约 16.5 秒一次。软件消不掉，只有可变刷新能消除。这次没有动。
2. 回调抖动造成的额外丢帧。相位靠近刷新边界时生成帧偶尔赶不上，屏幕队列被占住，等约 1 ms 仍没有空位就丢掉（`[fg-drops] capacity`）。

第二种取决于采集卡。日志里的回调抖动：MCS T911 和 KUHAIMI G50 是 0.01–0.06 ms，KUHAIMI 4K60 Version（4K30）是 1.87 ms。11-01 实测注入的 1.9 ms 只代表最后这张卡。

## 改动

`liveSmoothedCapacityWaitMs(输出间隔, 回调抖动)`：

| 输出间隔 | 等待 |
|---|---|
| 短于 12.5 ms（高于 80 fps） | 原规则，不看抖动 |
| 12.5 ms 及以上 | `1 + 3.125 × 平均偏差`，下限是原规则，上限 3 ms |

- 平均偏差是 `LiveArrivalSmoother::jitterMs()`，约等于 0.8 倍标准差，所以公式等于 `1 + 2.5 × sd`。
- 只影响显式垂直同步下的图内补帧，且只在平滑锚点生效时（物理和屏幕采集）。自动模式没有这个等待。内容去重和串流没有平滑锚点，仍是原来的 2 ms。
- `[live-anchor]` 增加 `capacityWaitMs`。自动模式下这个值只是算出来的，不起作用。
- `VEYRA_TEST_FIXED_CAPACITY_WAIT=1` 恢复固定等待，用于 A/B。
- 单测：`tests/unit/LivePresentationTimingTests.cpp`。

### 真实 60 Hz 实测

用户把本机屏幕切到 60.000 Hz（每轮日志都核对过）。RTX 5070，4K 片源按采集卡节奏回放，自身时钟偏 800 ppm，输出 59.74/s，垂直同步，2X。`verify.py wait hz60`、`hz60b`、`hz60c`，共 14 轮，全部退出 0，无 D3D12 错误。固定规则用 `VEYRA_TEST_FIXED_CAPACITY_WAIT=1`，长轮次按“旧新新旧”交替。

统计跳过每轮前 5 秒。Codex 接手时复算了所有 14 轮原始日志（`reports/codex-vsync-handoff-20261101/evidence-review.json`）：

| 补帧 / 注入抖动 | 规则 | 稳定段 | 真实帧 / 生成帧提交数 | 提交数差折算每分钟 | 回调时钟拟合线→Present 结束均值 |
|---|---|---|---|---|---|
| DLSS / 1.9 ms | 固定 | 3 轮合计约 43 秒 | 1284 / 1257 | 37.7 | 21.88 ms |
| DLSS / 1.9 ms | 自适应 | 3 轮合计约 43 秒 | 1285 / 1281 | 5.6 | 21.97 ms |
| VFG 中档 / 1.9 ms | 固定 | 3 轮合计约 43 秒 | 1284 / 1280 | 5.6 | 21.85 ms |
| VFG 中档 / 1.9 ms | 自适应 | 3 轮合计约 43 秒 | 1286 / 1284 | 2.8 | 21.83 ms |
| DLSS / 0.05 ms | 固定 / 自适应 | 各约 9 秒 | 269/269、268/268 | 都为 0 | 21.87 / 21.92 ms |

这里计数来自应用的呈现提交记录，不是实际显示的帧。提交差还受统计窗口边界、生成准入与提供方输出影响，不能逐帧等同于容量丢弃。包括启动段的日志累计容量丢弃：DLSS 固定 29、自适应 10；VFG 中档 13→8，支持容量等待确实减少提前丢弃的方向。日志按秒记录累计值，尾部还可能有未记录的丢弃，不能把它当作结束时精确总数。

原结论“DLSS 少显示帧减少 85%”改为“短样本中的生成帧提交缺口减少约 85%”。VFG 是 4→2 的小样本，不能给稳定收益保证。回调时钟拟合线→Present 的均值差分别约 +0.095 ms、−0.018 ms，只是软件时刻，不是屏幕端到端延迟；也不保证零延迟代价。

原 `panel_est.py` 强制为每次提交分配互不重复的刷新格点，并拟合每秒延迟中位数。这个假设无法判断哪些提交实际被替换；原“上屏平均 +1.27/+0.39 ms”“重复帧/分”及其 P95/P99/最大值不再作为验收证据。原文件与脚本保留供追溯。原 `wait-*.json` 的 `captureToPresent*` 直接用 host 时间减相对媒体 PTS，也无物理意义，不采信。这里的误差不是靠增加小数精度能补救的。

中途纠错：第一版统计包含 DLSS 启动的前 2–3 秒，呈现 P95 一度读成 34 ms；两套规则都有该启动段，已排除前 5 秒。当前短测不足以证明所有尾延迟都没有增长。
