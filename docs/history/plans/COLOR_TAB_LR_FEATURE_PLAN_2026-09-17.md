范围：

1. 删除"参数与预设"窗口里的 **预设** 页（**代码级删除，不留任何入口**），替换为 **色彩** 选项卡；

不在范围：AI 蒙版（主体/天空/人物/风景）、画笔/深度蒙版、生成式移除与内容识别修复、内容凭证、ICC 软打样/色域警告、相机 DCP 配置文件库、Process Version。

## 0. 结论摘要

- 能做到**功能对齐 + 参数语义对齐 + 专业级观感**；做不到**逐像素等于 Lightroom**（相机配置文件、色调映射、AI 模型都是闭源黑盒）。任何"完全一样"的说法都是撒谎。
- 调色跑在**现有 FP16 线性工作图**上（`EnhanceGraph` 的工作纹理本来就是 `R16G16B16A16_FLOAT`），所以"高精度"这一条**不花额外延迟**；花延迟的是 pass 数量与全分辨率读写次数。防色带按"浮点链路 + 高精度 LUT + 输出抖动"三条落实。
- HDR 按标准做：线性光里调，PQ/HLG 走 BT.2100 EOTF 转换，SDR 参考白沿用代码里已有的 **203 cd/m²**（BT.2408）合同，导出重新计算/标注 MaxCLL / MaxFALL。
- 命名预设是**色彩外观预设**（含 LUT 引用），不恢复旧的增强参数预设页。

### 2.7 .cube LUT

规格要点（Adobe Cube LUT Specification 1.0）：`TITLE`、`LUT_1D_SIZE` / `LUT_3D_SIZE`、`DOMAIN_MIN`/`DOMAIN_MAX`（默认 0/1）、`#` 注释；数据为 0–1 浮点三元组；**3D 数据中第一分量（红）变化最快**；常见尺寸 17/33/65。

实现要求：

1. 支持 1D 与 3D；尺寸、域、行数、NaN 全部校验，不合格**拒绝导入并保留原文件**。
2. GPU 侧 = `Texture3D`（**RGBA16F，不用 8 位**）+ **四面体插值**（精度优先；65³ 可退化为硬件三线性以省带宽）。
3. 单个 65³ LUT ≈ 4.4 MB 显存；同时加载上限 8 个 + LRU 缓存；落地 `runtime_local/luts/*.cube` + manifest（名称、来源、尺寸、SHA-256）。
4. 控件：强度、输入空间（Cineon Log / sRGB 显示参考 / PQ）、启用开关；固定顺序"颜色分级之后、颗粒之前"。
5. 只接受 `.cube`；`.3dl/.mga/.look/.csp/HaldCLUT` 明确不支持。

## 3. UI 设计：色彩选项卡 + 风琴折叠（v2 更新）

### 3.1 结构

- "参数与预设"窗口页签：**增强 / 运动 / 色彩 / 导出**（"预设"页整页删除）。
- 色彩页 = 顶部工具条 + 可滚动风琴分组列表。

  - 按批复：**取消"仅显示已改动"开关**；取而代之的是顶部"一键还原"与每组右键"重置该组"。

### 3.2 分组顺序（与你截图一致）

1. 亮　2. 颜色　3. 曲线　4. 混色器（HSL/颜色/黑白）　5. 颜色分级　6. 细节　7. 效果　8. 光学　9. 校准　10. 点颜色　11. LUT

- **分组头**：左折叠三角 + 名称；右侧**眼睛** = 该组 bypass（灰=未启用）。单击折叠/展开；右键 = 重置该组 / 复制该组。

- **曲线**：自绘网格 + 控制点增删拖拽 + 通道下拉 + "拉平曲线"。

### 3.4 色彩预设（新增，按游戏切换）

- 列表 + "保存当前设置为预设"（命名 ≤48 字，重名需确认覆盖）+ 另存为 + 重命名 + 删除。

- 切换预设时**不重建图、不重连采集**，只更新 uniform 与 LUT 资源。

## 4. 精度与色带：为什么不是"滤镜"，会不会掉延迟（新增章节）

### 4.1 坏做法 vs 我们的做法

坏做法（必然出色带）：源 → 8 位 sRGB → 8 位 LUT → 8 位输出，每一步量化都在砍信息。

我们的做法：

1. **全链路浮点**：`EnhanceGraph` 工作纹理本来就是 `R16G16B16A16_FLOAT`（线性光），调色 pass 直接在这层做，**不新增 8 位中间纹理**。
2. **LUT 高精度**：曲线烘焙 FP16/1024 项 1D LUT；3D LUT 用 RGBA16F + 四面体插值；不用 8 位 LUT。
3. **运算顺序按色彩学来**：曝光/白平衡在线性光里乘除；对比度/曲线/分级在有明确挂载域的显示参考域或对数域做，绝不在 PQ/HLG 码值上直接做算术。
4. **输出抖动（dither）**：进 8 位 SDR 呈现/导出前加三角抖动，把量化误差变成不相关噪声而不是色带。
5. **源头色带可选缓解**：P2 增加可选"去色带（deband）"滤波（梯度检测 + 低幅噪声，参考 libplacebo/mpv 的 deband），UI 与日志明确它只减轻、不修复源头量化。

### 4.2 会不会大幅增加延迟？——不会；代价来自 pass 数量，不是位深

- 工作图本来就是 FP16 → "在线性浮点里调"**不增加带宽**；改成 FP32 只会白花一倍带宽。
- 真正开销是"每多一个全分辨率 pass 就多一次读写"。v4 决定：**只有一条链、只有一个 pass**，
  位置在所有效果器之前，因此它作用的是**源头分辨率**（1080p 源 ≈ 4K 工作图的 1/4 像素）。

| 新增工作 | 目标耗时（RTX 5070） |
| --- | --- |
| 色彩 pass（白平衡/曝光/曲线 1D LUT/HSL/黑白/分级/校准/3D LUT，单一 dispatch） | 1080p 源 ≤ 0.15 ms；4K 源 ≤ 0.35 ms |
| 直方图统计（降采样 + 每 200 ms 读回） | ≈ 0 |
| **关闭总开关时** | **0 ms（pass 不存在）** |

相对 4K60 的 16.6 ms，1080p 源的固定成本约 0.9%，4K 源约 2.1%。新增 `GpuStage::Grade` 计时，进
`player-timing` / `capture-timing` 日志（与现有 `gpuSrP95Ms` / `gpuNrP95Ms` 并列）；超预算按
3D LUT 四面体 → 硬件三线性 → 关 LUT 的顺序降级并写日志，**不允许静默降级**。

## 5. HDR 按 HDR 标准做（v2 重写）

现状（代码事实）：项目已有 HDR 合同 —— `MediaFileSource` / `ColorMetadata.h` 解析 mastering、MaxCLL、MaxFALL；`HdrToneMap.h` 已用 **203 cd/m²（BT.2408 的 SDR 参考白）** 与 HLG 1000-nit 参考显示；预览区分"原生 HDR 旁路显示"与"HDR→SDR 增强"。色彩模块必须接着这条合同走。

### 5.1 工作空间与转换

- 工作空间：**场景线性 + BT.2020 原色 + FP16**，允许超过 1.0（HDR 高光不截断）。
- HDR 输入：PQ 用 BT.2100 EOTF（0.0001–10000 cd/m²），HLG 用 BT.2100 OOTF（1000-nit 参考显示、系统 gamma）；**先解析出绝对亮度语义再做线性运算**。
- 输出：按 sink 重新编码回 PQ / HLG，或走既有 HDR→SDR 路径；每步在日志写明传输函数与峰值来源（沿用 `hdr-metadata` 日志风格）。

### 5.2 各控件在 HDR 下的定义

| 控件组 | HDR 下的做法 |
| --- | --- |
| 曝光 | 线性光乘 2^EV，参考白/峰值随元数据变化，不改变相对内容 |
| 白平衡 / 校准 | 线性光 CAT / 3×3 原色矩阵，作用域与 SDR 一致 |
| 对比度 / 高光 / 阴影 / 白色 / 黑色 | 在**对数域或线性域**做分区曲线，参考点 = SDR 参考白 203 cd/m² 与内容峰值；不在 PQ 码值上直接加 |
| 曲线 | 明确挂载域：默认"对数域（Cineon/ACEScct 风格）"，可选 PQ 域；UI 标注当前域 |
| 混色器 / 点颜色 / 颜色分级 | 在保持亮度的感知空间做（OkLab 或 ICtCp，实现时定一个并写死），HDR 色域映射按 BT.2408 图形白与 BT.2020 容器处理 |
| LUT | 必须选输入空间：**Cineon Log（默认，创作者 LUT）** / sRGB 显示参考（SDR 内容或 SDR 参考域模式） / PQ；错误组合被拒绝并提示，**不允许静默按 sRGB 套 HDR** |
| 颗粒 / 晕影 | 线性域生成后按亮度归一化叠加，避免暗部被颗粒抬起色度 |

### 5.3 元数据与导出

- 调色改变峰值与内容亮度分布 → 导出时**重新计算并写入 MaxCLL / MaxFALL**（能测就测）；mastering 峰值无法测量时保留原值并标注"未更新"，不允许静默写入与实际不符的静态元数据。
- 字幕/OSD 属于图形白（BT.2408 图形白），不参与调色、不参与颗粒/晕影。
- 保持既有区分：HDR 原生旁路显示 ≠ HDR→SDR 增强；任何情况下不得把 SDR 结果冒充 HDR。

## 6. 技术插入点 / 持久化

### 6.1 插入位置（三入口共享一张图）

**v4 顺序（全部前移，只有一条链）**：

```
源（采集卡 / 文件 / 图片）
  → 上传 + YUV/打包格式 → 线性 FP16（源头分辨率）
  → 【色彩 pass】白平衡 · 曝光 · 曲线 · HSL/黑白 · 颜色分级 · 校准 · 3D LUT   ← 唯一位于效果器之前的调色
  → SR（DLSS / RTX Video SR / FSR，可选）
  → NR（DLSS-NR，可选） → 残差合成
  → 补帧（DLSSG / XeSS / FSR，可选）
  → 缩放 blit → 字幕/OSD 合成（不参与调色）→ sink（预览 / 截图 / 导出）
```

理由（按你的判断执行）：调色越早接触原始画面，作用的就是真实源像素，而不是 NR 重建/SR 放大之后的
像素；同时源头分辨率下做调色更便宜。代价写在 §10：效果器从此看到的是**带外观的画面**。

**总开关语义**

- 新增 `ColorSettings::enabled`（T2b 落地，默认 **关**，与"首次启动效果全关"的产品策略一致）；改任意色彩参数时自动打开（与 NR/超分开关的交互一致），UI 必须显示状态。
- 关闭时：**不创建**色彩 pass 的资源、**不 dispatch**、下游 SR/NR 的输入采样点直接指回未调色的线性图 → 与本轮之前的链路逐像素一致（验收项之一），开销为 0。
- 打开/关闭属于**链路形状变化**：允许重建图（和 NR/SR 开关同级别），但**改色彩参数本身不重建**，
  只更新 uniform / LUT 资源（`ColorSettings::enabled` 是 `sameVideoConfiguration()` 的比较项，
  其余色彩字段是排除项）。
- 三个入口（预览 / 截图 / 导出）共用同一张图与同一个 pass；导出时 `enabled` 与参数跟随当前设置。

### 6.2 设置模型与持久化

- 新增 `struct ColorSettings`（白平衡/亮/颜色/曲线/混色器/黑白/点颜色/分级/细节/效果/光学/校准/LUT），并入 `EnhancementSettings`。
- 色彩字段加入 `sameVideoConfiguration()` 的**排除清单**：改调色只更新 uniform / LUT 资源，**不重建图、不重连采集**。
- 落盘：`color-settings.v1`（当前）+ `color-looks.v1`（命名预设）+ `runtime_local/luts/` + manifest。

## 10. 风险与明确不做

**风险**：

1. **效果器看到的画面被改了**（v4 最大的代价）：DLSS-NR / RTX Video SR / FSR / DLSSG 都是在"自然画面"上训练的，
   把强曲线/强 LUT 塞到它们前面，可能出现 NR 判断变化、SR 伪影、补帧不连续。已在 §9 加了 1c 验收项，
   并且总开关默认关闭——最坏情况用户关掉调色就回到今天的画面。
2. LUT 在 HDR 上的错误映射（输入空间选择 + 拒绝错误组合 + 日志兜底）。
3. 曲线/色轮是新自绘控件，需要 UI 合同测试。
4. 观感与 LR 存在差异（文档与 UI 都写明"语义对齐，非逐像素复刻"）。

**明确不做**：AI 蒙版、画笔/深度蒙版、生成式移除与内容识别修复、内容凭证、ICC 软打样/色域警告、相机 DCP 配置文件库、Process Version，以及本次已取消的"仅显示已改动"。
