目标是减少可避免的排队、迟到后突发提交和呈现间隔波动，同时保护音画同步。FPS 数字平滑不等于画面平滑，不能修改统计口径制造改善。当前只确认共享 CPU 线程存在阻塞呈现的结构风险，尚未取得本次反馈的逐帧记录，不能宣称已找到用户机器的唯一根因。

新装与升级均默认关闭。保留 RTX 30/40/50 的现有 DLSS 2X–6X 选择，不通过降低倍数、停音频或放慢媒体时钟完成本功能。范围为文件、采集和 PS5 的实时预览；图片、暂停单帧处理和视频导出不受新增限速策略影响。

## 设置与用户可见行为

在现有播放/补帧设置区域增加“帧同步”总开关，默认关闭。开启后可选以下三个模式，总计四种状态：

| 状态/模式 | 具体行为 | 延迟与限制 |
| --- | --- | --- |
| 关闭 | 不启用本功能增加的节奏等待、队列限制、VSync 请求或 Reflex 调用；恢复关闭基线 | 仍有正常音画同步、补帧前后帧依赖及系统呈现延迟 |
| 低排队 | 根据真实 PTS、处理耗时和可用呈现容量安排工作，减少提前堆积；不额外缓存一整张源帧 | 以降低队列驻留为目标；输入断供时不能保证均匀输出，也不保证所有机器延迟下降 |
| 均匀呈现（前沿） | 在最终 Present 前按输出时间线安排提交，结合资源就绪与显示背压；迟到不成串追赶 | 允许有限余量换节奏，新增软件保留时间设计上最多一个输出帧间隔；不是端到端延迟上限 |
| NVIDIA Reflex（实验） | 无补帧时原生 NVAPI Sleep/markers；开启 FG 时显式回退低排队 | 本机接口成功、可关闭；未证明额外性能收益，多帧原生标记整合未完成 |

总开关首次开启时默认选“低排队”，之后记住用户最后选择。上述“低排队”与现有改变 NR/SR 执行顺序的“低延迟模式”是不同设置，不能复用其字段或自动修改处理顺序。

总开关下另设“显示同步”下拉选项，与节奏模式分开保存：

- **允许撕裂（默认）**：支持时使用 Present(0) 与 tearing，不请求 VSync；可能出现撕裂。此路径并不天然排斥 VRR。
- **垂直同步**：请求 VSync，避免撕裂；可能增加显示背压与延迟，不承诺最低延迟。
- **自动**：按当前输出与呈现能力选择经过验证的同步策略；无法确认 VRR 生效时保守采用兼容的 VSync 路径，状态显示实际选择。硬件支持 VRR 不等于当前 G-SYNC 正在生效。

总开关关闭时，上述下拉控件禁用但保留偏好，实际撤销本功能的显示同步请求。模式切换不覆盖用户的显示同步选择。软件不更改 NVIDIA App、控制面板或显示器设置，不将“刷新率减 3”当作通用规则。首轮不增加自定义 FPS 上限，避免再增加一套相互冲突的限速器。

24fps×6=144fps，但 120Hz 屏幕无法每秒完整显示 144 张不同画面。保持用户 6X 设置；需要选择预览呈现帧时如实记录跳过数量，不偷偷改变源速率。23.976 等时间基保持有理数精度，不四舍五入成 24/144 后长期累积误差。

## “完全关闭”的执行合同

关闭必须是运行时撤销，不只是隐藏 UI 或保存布尔值：

1. 在拥有线程应用新的策略版本，唤醒本功能的定时等待、容量等待和暂停等待；废止旧策略的 deadline 与排队额度，不继续执行旧版本回调。
2. 若启用过 Reflex，调用关闭配置撤销低延迟模式、限速与 boost，检查返回值；之后停止本功能的周期性 Sleep/markers 调用。关闭失败必须显示真实状态，不冒充已关闭。
3. 恢复基线交换链呈现参数与最大帧延迟配置；若需要重建交换链，按生命周期规则一次性排空相关资源，不逐帧等待 GPU，不中断稳态音频。
4. 模式转换使用 requested/effective/revision 状态；只在拥有线程提交有效状态，UI 不先显示“已生效”。失败时明确保留原生效模式或退回关闭，不暗中换另一种模式。
5. 用户关闭决定立即持久化，下次启动不得重新启用；其他模式在成功应用后保存。退出时再次保存，画质预设不携带该设置。

关闭不能撤销 GPU fence 的资源安全约束、原有 PTS/音画同步、补帧算法等待后一帧、提供方自身必要调度或 Windows/DWM/驱动设置。它的准确含义是完全关闭本次新增策略，不是承诺零等待或零延迟。

独立确认的错误调度与资源生命周期修复对所有模式保留，关闭不应重新启用已修复的 bug。关闭的验收针对“没有新增可选策略开销”，同时用原始基线比较行为。

## 调度与后端边界

每条呈现路径只有一个节奏控制拥有者。统一处理媒体 PTS、GPU 就绪、显示容量和取消信号，不叠加多个互相争用的等待循环。不在每个 pass 增加 CPU fence wait，不创建第二套 EnhanceGraph 或播放循环。

| 路径 | 处理原则 |
| --- | --- |
| 自有交换链，无补帧 / DLSS 2X–6X | 软件模式主要接入点；复用现有独立 GPU present queue 与有界 lease/fence 生命周期 |
| XeSS 或现存 FSR 提供方呈现 | 保留提供方调度拥有权；只有确认其公开能力后才传递对应策略，不在外层重复 pacing。暂不支持的模式显示未生效原因，保持补帧开启及用户偏好，不恢复已撤掉的 FSR UI |
| Smooth Motion | 不改驱动设置，不控制或统计驱动生成帧；外部 RTSS/驱动限速可能叠加，纳入对照记录 |
| 导出 / 图片 / 暂停单帧 | 不套用预览节奏控制，不恢复导出资格门禁或结束逐帧扫描 |

RTSS 的 Async、Front Edge Sync 和 Reflex limiter 是不同机制，不能当作同一种 NVIDIA 技术。Front Edge Sync 指在原始 Present 调用前等待，不等于在 GPU 开始渲染前等待；Async 不代表没有阻塞或自动异步解码。本方案借鉴其等待位置的区分，不宣称复刻 RTSS 算法。

RTSS 作者讨论入口：<https://forums.guru3d.com/threads/understanding-fes-mode-is-front-edge-sync-mode-visually-smoother-looking-than-async-back-edge.456412/>。本轮此前仅检索到搜索摘要，论坛正文返回 403；未审计其实现源码和许可，不移植 RTSS 二进制。官方接口依据沿用研究记录中的 NVIDIA/NVAPI 文档，施工时固定实际版本与许可。

### 阻塞与迟到

先测同步 demux/decode、graph CPU 提交、GPU 依赖和 Present 的分别耗时。如果输入读取阻塞已就绪帧的呈现，优先增加有界预取与可中断读取；队列上限同时约束帧数、时间跨度及内存。不能照搬实时采集的容量 1 mailbox 到文件播放并随意丢弃解码帧。

如果输入隔离后仍需独立呈现线程，先完成显式拥有权设计：图提交线程产生不可变帧任务，呈现拥有线程处理最终字幕/OSD 与 Present；跨线程只传带版本和 fence 的 lease。等待 GPU 依赖使用队列机制，CPU 只在资源轮转必要时等待，不复制纹理形成无界缓存。

均匀模式使用绝对 deadline，避免按“上次醒来时间 + 间隔”累计漂移。迟到时按真实媒体时钟选取仍有显示价值的预览帧，不将过期子帧挤成一串，也不通过延后整条媒体时钟偿还积压。只在受影响的历史边界执行必要 reset，不能每漏呈现一张生成帧就无条件重建全部特征。

seek、源切换、resize、暂停恢复和 device lost 统一使旧任务失效，保持既有历史 reset 合同，禁止旧 epoch 帧重新出现在画面上。

### Reflex 可行性关口

保持直接 NGX，不引入 Streamline。先核对 `NvAPI_D3D_SetSleepMode`、`NvAPI_D3D_Sleep` 和 `NvAPI_D3D_SetLatencyMarker` 的设备、线程与帧边界合同，明确源帧和 MFG 子帧的 ID 对应。不能对每张子帧套用源帧限速，不能拿不存在的游戏 simulation/input 阶段制造延迟读数。

完整 Reflex+FG 原计划要求接口成功、实际排队变化、可关闭、2X/4X/6X 稳定及音画证据。本轮只交付无补帧的 Reflex 实验调用和有明确状态提示的 FG 回退，不能把整个 Reflex 计划标记完成。无补帧实测未显示优于低排队的额外收益。50 系硬件 Flip Metering 仍是单独研究项，不凭型号或接口成功声称已经接入。
