## 1. 判断及边界

目前不能把所有反馈归为补帧预算过严，也不能把低 GPU 占用解释为必然有余量。
连续输出至少要求：输入持续到达、源画面被处理、时间历史匹配、生成图像有效、
图像按正确时间顺序呈现。这些环节中任意一处断档，都可能得到很高的平均 FPS
和很差的观感。不能只修 FPS 数字。

用户报告的“约 15 秒”只表示间歇性，不是固定周期。用户观察到欠速与闪烁相关，
这是关键复现条件，但还没有证明“丢帧必然导致亮度闪烁”。必须区分：

- 运动停顿/追赶：画面时间位置或输出节奏不连续。
- 纹理、亮度交替：历史恢复、原帧/生成帧颜色或图像内容不一致。
- 整屏色调变化：HDR 输出状态/交换链重建或系统显示路径变化。

本轮没有新增性能运行，也未复现用户的实际闪烁。不能宣称已找出唯一根因，
不能给成功概率保证。正式版、已有测试包、本地未提交候选分别记录。

## 4. 修复顺序与具体交付

### A. 先补采集身份合同，独立解决重开选错模式风险

让采集打开请求携带稳定设备路径和已选格式键，打开时重新解析匹配项，
最近打开复用相同合同。旧数字 URI 兼容解析，但不能凭不存在的键假装验证成功；
无法可靠还原时交回选择器确认。GetFormat/最终连接类型核对尺寸、格式、
默认或自定义帧周期，以及用户色彩覆盖，不擅自降分辨率或换格式。
重连沿用现有稳定键逻辑，补默认 FPS 核对；合法驱动帧周期舍入需容差，不能要求浮点相等。

验收：枚举重排、模式删除、驱动拒绝/改写请求、旧 URI、最近打开、断线重连；
明确区分用户改选与程序恢复。修改边界为 capture request/parser/store/open，不改 NGX。
这个缺口可以直接修，仍不得宣传为用户变糊已确认修复。

### B. 找到第一次断供的位置，再修卡顿放大链

复用现有 frame-flow、reset、callback、CPU stall 和 fence 信息，按异常前后关联：
采集回调进入/退出 -> mailbox -> 读源 -> 图提交/完成 -> 呈现进入/退出。
视频输入对应为 demux/decode -> 已解码帧 -> 后续公共链，不能只跑文件就宣布实卡通过。

只补缺失的关键边界：必要时用固定容量内存环保存异常前后片段，一次导出，
不用逐帧字符串/磁盘记录。CPU 长调用用短 ETW 等待栈区分被抢占、互斥锁、驱动调用、
磁盘写和 GPU 等待；现有约第 605 帧 NR Evaluate 30ms 是 CPU 墙钟观察，不是 NR GPU 耗时证明。

按证据采取对应修改：

- 若回调被应用锁/I/O拖住，移出锁内日志/管理操作；必要时使用有界日志写出，
  实时回调不等待磁盘。先用受控慢 writer 验证隔离，再测实际收益。
  历史“关逐帧日志仍卡”的反证保留，此项不重复作为通用 FPS 优化。
- 若 owner 被非呈现管理调用拖住，仅把该已确认调用改成有界状态查询/缓存交接，
  不移动整个 GPU/Present owner，不添加视频排队。
- 若 CPU 在运行而 GPU 依赖未完成，定位具体依赖/工作，不删除 fence，不用占用率判空闲。
- 若应用没有阻塞而驱动确实停供，保留真实断点，修恢复后的额外停顿；
  不伪造缺失输入，不以此推断其他机器都是硬件问题。

验收：在相同输入/效果下减少已归因的停顿，源覆盖与帧龄不退步；有意断供时
恢复时间和图像状态正确。不能只比较异常恢复后的快帧，必须包含整个断档。

### C. 两后端一起验欠速恢复的画面，先 2X

复现正常 -> 短时处理延迟/输入断点 -> 恢复，分别控制每个边界，避免同时改多个因素。
用确定运动轨迹及含静态灰块/色块的素材区分画面运动和亮度脉冲，
对照相同真实源帧在连续运行与中断恢复时的输出。像素抓取仅用于独立诊断运行。

DLSS 核对源对、子帧时间位置、有效状态、播种后第一完整组，以及原帧/生成帧
进入最终 SDR/HDR 输出时是否使用同一颜色合同。XeSS 核对 source identity、
motionPreviousSource、XeLL 周期、reset 与 provider 实际消费的纹理对应，
消费结束以前不得复用资源；不能把外层 Present 返回当成组内每帧完成。
NR/SR 也一起核对：重置前后残差、保护合成和 HDR 基底是否与当前源对一致。

只修改被测试击中的身份、资源退休或恢复状态错误；保留真实断点 reset，
不把“生成失败”“没有显示”“算法历史无效”混成同一种状态。
不撤销已验证的单次播种、不引入默认防闪滤镜掩盖错误、不靠锐化减少所谓果冻。
当前没有证据支持直接全盘重写算法模块。

有源断档时不能创造缺失的真实运动；目标是恢复正确且不额外闪烁/反复播种。
若画面内容正确但呈现仍突发，再处理确切的期限/已就绪帧错序问题。
没有错误拒绝证据时不改 admission；5090 当前记录尤其不支持放宽限制。

### D. 单独验收 HDR 查询失败候选

本轮开始前已有 `HdrDisplayState`/optional 查询未提交修改。区分 HDR、SDR、查询失败：
同显示目标查询失败不应伪装为用户关闭 HDR；新会话/显示目标变化必须重新建立状态，
不能无限沿用旧显示器状态。测试失败注入、明确关闭 HDR、切换显示目标和结束重开。
现有候选只构建未运行，不算完成；此轮不继续改代码。
若欠速 SDR 也闪，必须继续 C，不能用 D 结案。

### E. 采集清晰度独立验收

先确认实际输入模式与全关效果的 1:1 像素，核对步长、平面、裁切、range/matrix/transfer。
再用同模式、同窗口可视尺寸比较 PotPlayer；若两程序不能同时打开卡，采用可重复信号顺序采集。
不能拿 HDMI 直连或不同锐化/缩放档作为无损对照。

若损失发生在色度重建或最终缩放，复用项目已有正确采样实现，按色度位置/缩放比接入，
逐项测线条、彩色边缘、文字、HDR 数值和 GPU 成本。不全局抬锐度，不伪造 4:4:4 细节。
若原始 4K 样本已模糊而软件 1:1 正确，记录输入端差异，不能再加“软件清晰度修复”。

## 5. 明确不再安排的旧实验

已对照 [实验索引](../reports/FG_EXPERIMENT_INDEX_2026-09-21.md)、
[非 NR 回退](../reports/FG_NON_NR_EXPERIMENTS_2026-09-20.md)、
[恢复修复反证](../reports/DLSS_RECOVERY_REPAIR_2026-09-20.md)、
[修复总账](../reports/POST_1_4_3_REPAIR_LEDGER_2026-09-21.md)。以下没有进入本方案施工项：

- 全局取消 admission/无限接纳晚到 FG（204.10 -> 184.76 提交/s，丢源/过期更多）。
- 同组 GPU 成本估算器、取消呈现清屏、光流历史复制、原生光流尺寸直传、提高队列优先级。
- XeSS 缩成一组 pending（约 52.25 -> 49.48 源帧/s，另有启动问题）。
- NVOF/SR 重叠、简单拆 CPU/presenter/owner、逐输出发布，以及换名的 FG/Enhance 并行重叠。
- 扩队列、固定 20/35/50ms 等待、自动降倍率/减画质、拖动时停止生成。
- 把含 provider 等待的 Present 周期反馈给 XeSS；采集设置固定 2 秒超时。
- 取消全部 discontinuity/reset，或把已有 sticky driver flag 修复重新实现一次。

**已有候选不是新方向：** `VEYRA_TEST_XESS_SOURCE_TIMING` 默认关闭，有吞吐收益，
完整节奏/图像未验收；仅在 C 的输入身份和资源合同通过后完成候选验收，不重新包装为新优化。
SDK 允许 frameRenderTime=0，不能把当前默认值直接判为违规。

## 6. 验收及有限停止条件

先验证效果全关，再 DLSS 2X / XeSS 2X；追加 NR+FG、SR+NR+FG、HDR 组合，
效果顺序、原生/内部/输出尺寸和光流档固定。之后覆盖 DLSS 3/4/6X、XeSS 3/4X，
源 30/60fps 及文件 24fps；XeSS 没有 6X。文件、原生采集、压缩采集分别标记覆盖。
1.4.0 当前对照构建未成功，不能声称已做可运行版本对比；后续用能运行的固定基线，
版本差异缩小到出问题的合同，不把整个旧版替换当前修复。

先做最小 30 秒交错对照；有收益再 120 秒，单次不超过 300 秒。
比较全段源覆盖、有效生成、间隔 P95/P99/最大值、长空档/突发比例、同起止点帧龄、
像素/运动正确性、CPU/GPU 关键路径。同期监测本身开销单列；不同阶段 P95 不能相加。
GPU 利用率和功率只作辅助。应用/SDK 提交不等于系统显示，更不等于屏幕到人眼延迟。

满速工况沿用 [运行方案验收标准](FG_RUNTIME_REPAIR_PLAN_2026-09-21.md#7-验收标准)，
逐输出事件可观测时才计算组内节奏。欠速优化至少要求长间隔/P99改善超过基线波动，
源覆盖、有效生成、画质和帧龄不退步；不能通过丢更多原帧、多排一帧或重复画面达标。
正确性修复和性能收益分开，不能以单元测试通过宣称用户闪烁消失。

每项独立 checkpoint；一次最小实现，最多一次有新证据的修订，无收益或负优化则撤回
本项改动并记录。发现纯运行时/GPU关键路径超预算且没有已证实的可去除阻塞，就停止
该性能实验，报告可用边界，不自动降档，也不以 GPU 百分比低继续无限尝试。

相关回归：后端/倍率切换、seek、暂停/恢复、切镜、resize/跨屏、中键拖动、退出、
输入断开、HDR、字幕、截图；共享处理图变更加导出回归。没有实卡/第二屏就明确未测。
不把本机 RTX 5070 结果代替 30/40/5090 或反馈者实机结果。
