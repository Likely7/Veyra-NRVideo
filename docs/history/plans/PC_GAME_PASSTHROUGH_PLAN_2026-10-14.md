## 0. 结论

在 Veyra 进程内做“游戏模式”：捕获游戏窗口，Veyra 全屏盖在游戏上，置顶、鼠标穿透、不抢焦点。
游戏始终是前台窗口，拿到真实的键鼠（Raw Input）和手柄。要调画面时按 Home，Veyra 临时收回操作并打开
本轮已做好的 Home 调整面板（列表或节点画布）；关掉面板，操作自动还给游戏。

粉丝插件的核心原理是对的（置顶 + 分层 + 鼠标穿透 + 不激活，游戏保持前台），我们沿用这个原理。
它的问题都出在外挂实现上：外部进程、读日志、低级键盘钩子、猜窗口。这些改成进程内实现就都能避免。

## 1. 现在“全屏捕获没法操作”的原因

1. **输入全进了 Veyra。** 捕获 Veyra 所在的显示器时，Veyra 用 `WDA_EXCLUDEFROMCAPTURE` 把自己从
   捕获里排除，所以画面里是 Veyra 底下的桌面或游戏。但 Veyra 的窗口仍然盖在上面，点击和键盘都进了
   Veyra，画面里的东西一个都点不到。切回游戏，游戏又盖住 Veyra，看不到增强后的画面。
   从首页开始捕获还会自动跳到极简（窗口模式），看上去就像卡住了。这件事只能靠穿透解决。
2. **自排除只做了一半（实测）。** 排除只在捕获打开的那一刻，对当时可见的自身窗口生效。极简和全屏的
   控制条是一个独立窗口，捕获开始约 0.1 秒后才显示（日志 `control window visible=true`）。实测它的
   affinity 为 `0x0`，主窗口为 `0x11`，所以控制条会被捕获进画面，形成画中画。
3. **两个鼠标指针。** 捕获默认带指针。Veyra 在同一块屏幕全屏时，画面里会多出一个延迟的指针，
   真指针在它上面。
4. **副作用：** 显示器捕获期间，Veyra 对 OBS 和截图不可见（PrintWindow 实测全黑）。窗口捕获没有这个问题。

（本轮已修好：极简模式全屏按 Home 呼出专业模式调整菜单，节点模式呼出节点画布。）

## 2. 粉丝插件分析（VeyraOverlay，C#，外部 exe）

做法：

- 外部进程找到 `veyra_qml_ui` 的主窗口。按 Alt+F8 时给它加上
  `TOPMOST | LAYERED | TRANSPARENT | NOACTIVATE`（`0x8080028`），再把前台交给窗口中心下面的那个窗口。
- 读 Veyra 日志尾部 40 KB：最后一行 `[screen] opened` 在 `session=0` 之后，就认为在屏幕捕获。
- 用 `WH_KEYBOARD_LL` 和 `WH_MOUSE_LL` 低级钩子收热键。Alt + 双击左上角强制释放；再启动一次 exe
  会清掉残留样式。
- 默认不自动穿透（`autoOn=0`），要手动按一次 Alt+F8。

可取之处：原理正确；默认手动开启；准备了多个出口。

问题：

| 问题 | 后果 |
|---|---|
| 外部进程改 Veyra 的窗口样式 | 任何一方崩溃或更新都可能留下穿透样式。README 写了用户被锁住，只能 Ctrl+Alt+Del 或重启 |
| 读日志判断状态 | 日志格式一变就失效；只认“屏幕捕获”这一种来源 |
| 低级键盘钩子 | 必须有消息泵，修饰键状态要自己维护（他们都踩过坑）；本质是全局键盘监听，部分反作弊会拦 |
| 交焦点靠 `WindowFromPoint` 猜“下面的窗口” | 它自己的日志里就是 `focus -> game: FAILED` |
| 置顶后不管 Alt+Tab | 切到聊天或浏览器时，这些窗口被 Veyra 盖住 |
| 不处理指针和对齐 | 捕获带指针时出现两个指针；游戏窗口和 Veyra 画面大小不同时，点击位置对不上 |
| 只改一个“主窗口” | 控制条等独立窗口不受控 |
| 只能用键盘切换 | 手柄玩家要伸手去按键盘 |

## 3. 方案：进程内游戏模式

### 3.1 用户流程

1. **入口：** 在来源菜单加“PC 游戏”，打开屏幕捕获对话框的游戏模式（默认选窗口捕获，列出可见的
   大窗口）。也可以在捕获对话框里加“游戏模式”开关，两者内部是同一个流程。
2. **开始：** Veyra 在游戏所在的显示器上全屏，关闭捕获指针。屏幕中央显示：
   “3 秒后把操作交给游戏 · Home 调整画面 · Ctrl+Alt+Home 退出游戏模式”。倒计时期间可以取消。
3. **游戏中：** 穿透开启，焦点交给游戏，键鼠和手柄都直接操作游戏。
4. **调整画面：** 按 Home（游戏模式下全局生效）→ Veyra 收回操作，打开调整面板（列表或节点画布，
   和本轮的 Home 面板一致）。再按 Home、按 Esc 或点击画面 → 关闭面板，操作自动还给游戏。
5. **结束：** 游戏关闭、捕获结束或按 Ctrl+Alt+Home → 撤销穿透，回到正常界面。

### 3.2 关键机制

1. **窗口样式（GUI 线程，进程内）**
   - 主窗口和其它可见的自身顶层窗口：exstyle 加上 `WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_NOACTIVATE`，
     再 `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)`。
   - 保存原值，退出时精确还原。收到 `WM_STYLECHANGED` 时检查，如被 Qt 改回就重新施加。
   - 穿透期间控制条不显示。
   - Veyra 一退出或崩溃，窗口随进程消失，不可能残留“盖住屏幕又点不动”的窗口。
2. **热键：用 `RegisterHotKey`，不用低级钩子**
   - 系统级热键，没有消息泵和修饰键的问题，也不监听其它按键。
   - Home 只在穿透期间、且游戏在前台时注册；别的程序到前台时注销，不抢它们的 Home。
   - Ctrl+Alt+Home 固定作为退出游戏模式的键。两个热键都可以在 设置 → 快捷键 里改。
   - 任何一个热键注册失败（被别的软件占用）就拒绝进入穿透并提示。永远不进入没有出口的状态。
3. **交焦点**
   - 窗口捕获：捕获目标就是游戏的 HWND，直接 `SetForegroundWindow`，不用猜。
   - 显示器捕获：取 Veyra 下面 z 序中第一个可见的普通窗口，再参考最近一次非 Veyra 的前台窗口。
   - Veyra 自己是前台进程时（点开始、关面板），系统允许它把前台交出去。收到热键时通常也允许；
     失败时用 `AttachThreadInput` 兜底。结果一律写日志。
4. **跟随游戏（解决 Alt+Tab）**
   - 用 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT)` 跟踪前台窗口。
   - 同一块屏幕上的第三方程序到前台 → Veyra 退出置顶，排到游戏正上方，第三方程序可见。
   - 游戏回到前台 → 立即重新置顶（不激活）。另一块屏幕上的程序不影响。
   - 游戏最小化 → 暂停穿透；游戏关闭 → 结束游戏模式。
5. **指针和对齐**
   - 游戏模式强制捕获不带指针。真指针由系统硬件光标画在最上层，没有延迟。
   - 对齐检查：游戏客户区与 Veyra 画面区域一致时（游戏无边框全屏、Veyra 同屏全屏、无裁剪、
     宽高比相同），点到哪里就是哪里。
   - 不一致时提示“请把游戏设为无边框全屏”，或改用“贴合游戏窗口”（P2）。
6. **自排除修正（显示器捕获）**
   - 捕获期间新显示的自身窗口也要排除。在 GUI 线程上、窗口显示时设置。
   - 不在引擎线程上调用窗口 API，避免 GUI 和引擎互相等待（10-10 冻结的教训）。
7. **兜底出口**
   - 进程内实现：崩溃等于窗口消失，不会残留。
   - GUI 卡死看门狗：穿透期间 GUI 线程 2 秒无响应时，由另一个线程调用 `ShowWindowAsync` 把 Veyra
     最小化（异步调用，自己不会被卡住），游戏马上可见、可操作。
   - 热键注册失败时不进入穿透。
   - 系统级出口：Win 键开始菜单、Ctrl+Alt+Del 永远可用。
   - 手柄长按 View+Menu 1 秒等同于 Home（P2，SDL3 后台手柄事件，remoteplay 里已有先例）。
8. **延迟**
   - 游戏模式默认用低延迟设置：低延迟队列开，显示同步“自动”或可变刷新，严格补帧节奏关。
   - 面板里显示端到端延迟估计。
   - 用 PresentMon 实测 Veyra 的送显模式和延迟。目标：比直接玩多出的延迟不超过 1 个游戏帧加补帧本身的开销。

### 3.3 不支持和限制

- **独占全屏游戏：** 系统不允许别的窗口盖在上面，捕获也常失败。检测到
  （`SHQueryUserNotificationState` 返回 `QUNS_RUNNING_D3D_FULL_SCREEN`）就提示改成无边框窗口。
- **游戏自己的行为：** 少数游戏完全被遮挡，或打开面板失焦时，会自己暂停或降帧。需要实测，列出名单。
- **反作弊：** 不注入、不挂钩子，只用 WGC 捕获加置顶窗口，和 OBS、Discord、Lossless Scaling 属于同类，
  风险低，但不能保证所有反作弊都放行。
- **声音：** 游戏声音由游戏自己播放（屏幕捕获不采音频），画面会比声音晚 Veyra 的处理时间。
- **双屏用户现在就能玩：** 游戏放主屏、Veyra 全屏放副屏，不需要穿透。适合鼠标被游戏锁定的 FPS；
  鼠标指针类游戏会把指针移到另一块屏幕上。

## 4. 实施切分

- **P1 核心**
  - `GamePassthrough` 类：样式、热键、交焦点、跟随前台、看门狗、日志。
  - 窗口捕获 + 无边框全屏游戏。
  - Home 面板联动、倒计时提示。
  - 游戏模式关闭捕获指针；显示器捕获的自排除修正。
- **P2**
  - 显示器捕获自动认出游戏窗口。
  - 贴合游戏窗口：窗口化游戏时，Veyra 无边框置顶贴在游戏客户区上，跟随移动和缩放。
  - 手柄长按；设置页的热键和默认项。
- **P3（可选）缩放模式**
  - 游戏用低分辨率窗口，Veyra 全屏放大，即用超分放大显示尺寸。
  - 需要 `ClipCursor`、指针速度换算和自绘指针，做法类似 Lossless Scaling。

预计改动范围：

- `apps/veyra-qml/main.cpp`：挂接原生消息过滤器。
- 新增 `GamePassthrough`：按现有定向构建方式写成 header-only。
- `QmlPlayerBridge`：游戏模式状态、开始和退出、捕获指针覆盖。
- `Main.qml`、`DialogHost.qml`、`SettingsPage.qml`：入口、提示、热键设置。
- `ScreenCaptureSource`：只暴露“是否为显示器捕获”，不在引擎线程上调用窗口 API。
- 不改补帧、NR、呈现算法。

## 5. 验收

- **测试游戏窗口**（自带 D3D12 程序，无边框全屏，记录 Raw Input、点击坐标和 XInput），检查：
  - 前台始终是游戏；
  - Raw Input 鼠标和键盘事件都能收到；
  - 点击坐标与 Veyra 画面一致；
  - 手柄可用。
- **真实游戏**：Raw Input 射击游戏、鼠标指针类策略游戏、手柄游戏各一款（避开强反作弊网游）。
- **出口**：
  - Home 和 Ctrl+Alt+Home；
  - 游戏关闭、捕获失败；
  - 杀掉 Veyra 进程后无残留；
  - 注入 GUI 卡死时，看门狗把 Veyra 最小化；
  - 热键被占用时拒绝进入。
- **其它**：
  - Alt+Tab 到同屏和另一块屏幕上的程序；
  - 显示器捕获时控制条 affinity 为 `0x11`，没有第二个指针；
  - PresentMon 对比游戏模式和普通全屏的送显模式与延迟。
