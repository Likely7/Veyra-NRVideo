### 1.1 产品决定

1. 首次启动和每次重新启动默认进入**日常模式**；专业模式不是另一个播放器，也不是另一套画质预设。
2. 日常模式负责视频观看和采集卡，强调大画面、轻控制。
3. 专业模式集中模型参数、变化量、SR/NR尺寸策略、2X/3X/4X、光流、内容节奏、预设管理、同帧比较、性能、诊断和图片/视频导出。
4. 两种模式共用当前源、增强设置、播放位置、音频状态和同一个视频显示宿主；切换不重开文件或采集设备。
5. 专业模式改好的参数，返回日常后继续生效；模式切换本身不降画质、不增加GPU负载、不提交新设置版本。
6. 导出只能在专业模式配置和启动。已有导出任务在返回日常后继续管理其生命周期，日常只显示简洁进度和“查看”入口。
7. 导出期间仍能观看：这是需要补齐的工程功能，不是当前代码已经具备的能力。不得以隐藏界面代替解耦任务。
8. 黑灰底、柔和白字、橙色重点；专业模式借图1的分区，日常模式借图2的大画面和底部播放条。不照搬无人机地图、罗盘、虚假仪表或电影品牌元素。

## 5. 状态模型：模式不是播放会话

### 5.1 唯一状态来源

建议新增UI层结构（名称可按项目约定调整，语义必须一致）：

```cpp
enum class UiMode { Daily, Professional };
enum class ProPage { Enhance, FrameGeneration, Presets, Export, Diagnostics };
enum class SourcePane { Video, Capture, Image };
struct UiSessionState {
    UiMode mode = UiMode::Daily;
    ProPage professionalPage = ProPage::Enhance;
    SourcePane sourcePane = SourcePane::Video;
    bool fullscreen = false;
    bool performanceExpanded = false;
    float inspectorWidthDip = 328;
};
```

这不是第二份PlayerSnapshot。播放状态、当前源、当前PTS、实际音量、字幕选择、Desired/Applied、错误和输出作业分别由所属服务提供快照。

禁止让日常与专业各自维护一个EngineController、PresetStore、paused、currentFile、settingsRevision或导出状态。

### 5.2 setUiMode合同

`setUiMode(target)`只允许：

1. 更新UiSessionState.mode、恢复专业页签/滚动位置。
2. 通过批量窗口布局一次提交目标矩形和可见性。
3. 更新焦点、可访问名称、mode按钮文字；使焦点不落在隐藏控件。
4. 通知Presenter最新显示区目标尺寸，等待显示线程按既有fence纪律处理。

不得调用：`EngineController::open/stop/post/startExport/requestSettings`、`source.open/close/seek`、`capture.configure/start/close`、`EnhanceGraph::initialize/shutdown/reset`或重新创建Feature。

只改变显示区大小可以resize swapchain；工作分辨率base/NR/FG不随面板尺寸改变。UI布局版本与enhancement settingsRevision必须分开。

### 5.3 “无缝”的可测试定义

- 切换中video HWND、活动source session ID、NR/SR/FG handles及同一播放任务保持不变。
- 没有因mode-change而出现SourceOpen/Close、seek、graph reset、epoch变化或settingsRevision变化。
- 原先暂停则继续暂停；原先播放则按媒体时钟推进，不回到0、不重复触发EOS重播；采集连接不重启。
- 音量、静音、字幕、选中预设、已应用参数及导出作业ID保持。
- 不展示空白/黑色过渡占位；可暂时保持最后一个有效GPU画面。显示资源resize若造成暂停要记录实际时间，不能宣称绝对零成本。
- 稳定60源fps合成文件、排除源scene cut/reset且没有导出负载时，模式切换造成的额外连续提交间隔目标不超过100ms；超过必须定位并修复，不从统计中删掉。
- UI模式命令处理耗时目标P95≤16ms，无单次>50ms；禁止在UI线程等待GPU fence、线程join、磁盘导出或设备枚举。
- 连续往返20次，句柄/GPU资源不线性增长，不重复注册事件/计时器。

可选120–180ms面板淡入，初版先实现正确的瞬时布局切换。不得逐动画帧改变video HWND大小触发连续ResizeBuffers；可先一次落到最终视频尺寸，再只对外围面板做视觉过渡。

### 5.4 比较状态的特殊处理

“输入原图/增强前底图”比较会抑制生成帧呈现，不应在日常模式隐藏地继续生效。返回日常时清除临时按住状态、将比较显示退出到增强画面，保留专业比较偏好供再次进入使用。这只是Presenter比较选择，不修改增强参数或reset历史。日志必须区分这一显示选择和增强设置。

### 5.5 启动与偏好持久化

- UiMode不持久化为启动专业；每次应用正常启动强制Daily。CLI导出worker不创建日常窗口。
- 窗口位置、专业面板宽度/上次页签、音量/静音、字幕显示偏好可保存在独立versioned UI配置中。
- 正常启动恢复最后一次**应用成功**的增强快照；无有效历史时用用户默认预设，再无则内建默认。Desired未确认的值、失败值、导出worker临时值不得写成下次启动设置。
- “设为默认”保存预设默认关系并明确说明用于恢复默认/无历史启动；它不悄悄覆盖正在播放的设置。若需载入，用户单独点“应用”。
- 不把UI偏好、最近媒体路径、设备索引混进EnhancementSettings或现有预设白名单。最近文件沿用独立存储；采集设备重连后重新枚举，不仅凭旧整数索引自动开机采集。
- 配置写入沿用临时文件、校验、原子替换；损坏保留原文件、走明确默认并展示可查看的诊断。写操作做去抖，不能拖滑杆每一像素就写磁盘。

## 6. 控件行为合同

### 6.1 传输与快捷键

| 操作 | 文件视频 | 采集卡 | 图片 |
|---|---|---|---|
| Space | 播放/暂停；不由控件文字推断状态 | 不实现冻结/回放，不触发stop | 无操作 |
| 进度拖动 | 拖动预览时间，松开提交一次seek；保持此前播放/暂停状态 | 不显示 | 不显示 |
| F11 / Alt+Enter / 双击视频 | 切全屏 | 同左 | 同左 |
| Esc | 先关闭最上层弹层；无弹层时退出全屏 | 同左 | 同左 |
| V按住 | 专业模式临时原图对比，释放/失焦立即恢复 | 专业同左 | 专业同左 |
| Ctrl+O | 打开文件，专业支持图片 | 打开后是明确源切换 | 同左 |
| Tab/Shift+Tab/方向键 | 正常焦点与控件操作 | 同左 | 同左 |

编辑框有焦点时，Space/V/方向键不得被全局拦截；Alt+Enter/F11仅按明确约定路由。隐藏控件不能仍接收键盘命令。导出快捷键即使从日常触发，也只能切到专业导出页，不直接启动导出。

### 6.2 日常增强总开关与预设

- “增强”总开关必须含义清楚：关闭时停止应用SR/NR/FG增强，恢复普通画面；不是仅隐藏效果但继续把全部GPU负载算成已关闭。
- 保存关闭前的完整有效设置作为可恢复配置；再次开启恢复它，不强制2X或重置强度。未曾开启某特性就不能凭总开关自动开启。
- 实现上区分“用户增强配置”与“本次有效启用状态”，最终仍通过唯一Desired/Applied事务入口提交；关闭不会删除专业参数值或改写预设文件。
- 关闭中的专业细调保存为待启用配置，控件明确标“增强已关闭”；用户显式开启后整套应用。不能显示参数已影响当前画面。
- 预设菜单显示存储中的真实名字；参数偏离已应用预设时显示“自定义”。比较快照忽略运行期revision，不凭名称猜是否相等。
- 日常选择重负载预设会显示“原生NR / 4X”等简述与负载警告；不能暗中改成轻量档。

### 6.3 专业参数编辑

- “增强”页：NR开关、SR底图目标、实时/原生NR策略；模型强度/局部明暗/局部结构；变化量五项；实验参数折叠。
- “补帧”页：关闭/2X/3X/4X、请求与实际能力、光流三档、内容节奏识别；解释补帧需等待下一源帧，不把采集延迟称免费未来帧。
- “预设”页：载入、新建、复制当前、重命名、删除、设默认、恢复内建默认；复用PresetStore，不重新发明存储格式。
- 数值编辑允许暂存未完整输入的“1.”等文本；按Enter或失焦时校验，非法值停留并提示，不提交NaN/半份配置。
- 普通连续参数滑杆采用短去抖（建议120ms），松开立即提交；同组更新合为一个完整快照。倍率/尺寸/光流等需要资源变更的控件只在用户完成选择后提交，不随拖动反复重建。
- Desired与Applied均可查；应用中显示请求值和当前生效值。失败回滚整个事务，并显示失败来源，不逐字段伪装部分成功。
- 从专业返回日常时，正在输入但尚未提交的文本保留为编辑草稿，不能因隐藏窗口自动提交非法数值。
- skin=-1使用明确“默认/未指定”选项，其余0–2；style为0/1/2整数；autoMask/UI为开关。肤质/UI效果未证实标签保留，不虚构官方含义或预设。

### 6.4 音量与字幕

- 新增本应用volume[0,1]、mute状态命令及快照，UI只更改当前应用音频，不调用系统总音量/设备主音量接口。
- 文件音频在现有WASAPI音频线程对float PCM应用短渐变增益，或采用经核实的本session增益；避免重新启动音频时钟和瞬时爆音。
- HDMI音频通过当前DirectShow音频渲染链获得本graph音量能力；COM操作在所属线程执行。能力不可用时显示“此音频输出不支持应用内音量”，不能画一个没有作用的滑杆。能静音也必须验证真实输出路径。
- 无音轨/未选采集音频时明确显示“无音轨/未启用监听”，避免显示虚假的有效音量状态。
- 字幕提供当前外部SRT显示开关、载入外部SRT与基础大小选择；不新增内嵌字幕解码、字幕烧录或翻译。
- 字幕、播放条和OSD只在最终显示层叠加，不能进入NR/FG输入。普通视频导出继续遵守原有不烧录字幕的边界。

## 7. 导出与观看并存：必要的工程改造

### 7.1 当前障碍与选择

当前`EngineController::startExport()`调用`post()`，会设置播放stop并把导出放到同一个worker。新UI若继续调用它，“返回日常继续看”就是假功能。

**本方案选用独立本地导出worker进程**：由当前Veyra.exe的无界面子模式调用共享`exportVideo()`和产品库，前台播放器保留原会话。不是再复制一套算法，也不同时在同一进程里盲目初始化第二套NGX全局状态。

现有`--export-out`证明无界面入口已存在，但完整冻结预设传递、进度/取消IPC、子进程生命周期仍待实现，不能直接当现成功能。

### 7.2 作业合同

建议新增`ExportJobManager`与只读`ExportJobSnapshot`：

- 一次最多1个活动导出任务；不增加无界队列。重复点击开始时展示现有任务。
- 状态：Idle → Preparing → Running ⇄ Paused → Finishing → Succeeded / Failed / Cancelled；取消请求与取消完成分开。
- 启动时冻结完整已应用设置、输入路径、输出路径、codec和导出尺寸策略；图像/视频路径不允许混用，采集源不支持“导出视频”按钮。
- 导出固定原生质量策略，不能继承日常实时NR降分辨率；冻结的settingsRevision和当前播放revision分别显示。
- 用户之后调播放参数、切模式、打开另一个视频，不影响已启动作业的源和设置。
- 工作进程使用已验证的当前EXE绝对路径与固定DLL加载机制；不启动脚本解释器、不拼接shell命令、不向环境PATH寻找程序。
- 任务描述与IPC按版本化白名单验证；路径属于显式用户输入，仅存在于本地任务通道，不写入用户预设或可复制诊断的明文路径。
- 优先使用本用户访问范围内的命名管道和随机job ID；父进程负责创建、认证/关联自己启动的子进程、限制报文长度和频率。不要对外开放网络端口。
- progress必须来自真实编码计数/时长，包含source/generated/Hold/output，不能按墙钟计时伪造百分比。100%只在flush/mux/回读检查和最终重命名全部成功后出现。
- 取消通过本作业IPC通知循环、结束编码、释放资源、保留partial；强制终止仅作为有时限的故障兜底，限制本作业进程树，不能按进程名杀所有Veyra。
- 父进程退出时先给合作取消和收尾时限，防止孤儿GPU作业。若仍在导出，关闭窗口提示“取消导出并退出 / 返回”；这是用户可能损失长任务的明确选择，不是每次模式切换弹确认。
- 已存在输出/partial继续拒绝覆盖；不自动删除失败文件。

### 7.3 并存不等于免费GPU性能

- 允许返回日常观看，但两进程仍共享物理GPU；不能承诺重负载导出与4K4X播放同时满速。
- 提供“观看优先”（默认）与“导出优先”。它们只影响导出作业节奏，不改播放画质、不丢播放源帧。
- 观看优先可在有界源帧边界暂停/节流导出：结合播放实际提交迟到、视频负载与GPU资源错误；不通过每个pass CPU等待节流，不持锁等待。
- 首版需要证明前台会话不中断、导出能继续/暂停/取消、状态一致；若该硬件无法并存，明确标“等待GPU资源”并保留作业及前台播放，不无声停止播放。
- 如果前台因当前SR4K+4X本来就低于源率，UI应显示已有瓶颈；不可把所有落后归给导出。
- 日常小进度条点击“查看”切到Professional/Export，操作本身不启动/暂停/取消任务。

保留原生窗口操作、标题栏拖动/双击最大化、最小化/最大化/关闭、任务栏和键盘可访问性。自绘标题区不能只画三个无法操作的按钮；最终须验证实际Windows窗口行为。

### 8.3 已有文件的改造规则

- SettingsWindow、TelemetryWindow分阶段提取可复用逻辑，再换嵌入式视图；删除旧入口前必须确保每项原功能在新界面可达。

- 输入设备枚举/格式查询在专用COM线程或已明确所有权的worker完成，以消息回主线程；结果过期可丢弃，不把查询绑定到每次UI刷新。
- snapshot消费建议4Hz，只刷新变化文本；进度显示可以本地平滑，但不能用插值计数当实测帧率。
- Resize调用合并到最后目标尺寸；UI线程不drainQueue。视频呈现和字幕叠加的线程/fence所有权明确，布局代码不能跨线程释放纹理。
- Direct2D UI渲染与D3D12视频分层明确，不把视频纹理读到CPU供UI绘制。控件/字幕覆盖视频需解决真实HWND层级，不靠普通STATIC透明背景假装透明覆盖。

## 10. 施工顺序与每步退出条件

每个UI阶段只由主Agent写入；代码变更先留工作记录。独立Reviewer只读，不替Maker改代码。未经实际检查不能把清单预勾为完成。

### UI0：盘点、保护与新基线

工作：完整读AGENTS及现有修复报告；记录git status/diff/stat、EXE/runtime身份、受保护文件hash；保存现有dirty patch；列出所有旧控件到新位置映射。

退出：基线可恢复，删掉的测试媒体保持删除，现有文件不被覆盖；本次仅文档阶段的状态明确。禁止用rehash消除漂移。

### UI1：共享状态与动作合同

工作：UiMode/UiSessionState、TransportState、CommandRouter、Layout纯函数；一个video HWND贯穿两种模式；建立模式切换计数/日志。

退出：在现有窗口上先验证切模式不调用open/stop/requestSettings，无媒体/播放/暂停状态一致；纯布局测试覆盖DPI和窄窗口。此阶段不先堆漂亮卡片。

### UI2：统一深色控件与日常模式

工作：Theme、底栏、空状态、顶部源入口与专业切换；文件播放/暂停/进度/最近文件可用；窗口布局和键盘焦点完整。

退出：真实视频可看，普通窗口不再出现专业参数/导出按钮；日常与现有引擎行为一致。不能用静态视频截图当播放。

### UI3：专业工作台与参数/预设迁移

工作：专业导航、右侧四页、原图对比/分屏；提取SettingsWindow/PresetStore逻辑；Desired/Applied和错误回滚可见；明确总增强开关状态与可恢复设置。

退出：全部7+5参数及倍率/尺寸/光流可达，预设CRUD完整，返回日常保留成功设置；失败注入整套回滚且NVOF不丢；缓存重算不增源帧计数。

### UI4：音量/字幕与采集界面

工作：补音频命令和快照、字幕显示控制；采集枚举异步化、连接状态、两种模式共享会话；采集底栏不显示seek。

退出：合成音频证明音量/静音作用于本应用输出且不改音频时钟；无设备/配置失败状态通过；实卡项标awaiting_user_capture_test，不借模拟通过冒充设备通过。

### UI5：后台导出任务

工作：独立worker、冻结配置通道、进度/取消/暂停、父子进程清理、专业Export页与日常小进度。

退出：同一视频导出时前台继续播放，切模式不换job ID；前台改设置不改变导出冻结快照；H.264/HEVC/CFR/音轨/partial行为不退化；不能用现有startExport停止播放器后仍宣称并存完成。

### UI6：性能、诊断与负载提示

工作：迁移TelemetryWindow；尺寸链摘要、GPU/CPU分项、实际提交频率、错误摘要、诊断脱敏预览；导出竞争和重负载提示。

## 12. 对抗式审查清单

实现者交付前逐项回答，Reviewer至少抽查这些失败方式：

1. 所谓两种模式是不是实际关闭/重开了播放器？隐藏窗口里的worker是否仍然重复工作？
2. 专业切日常是否通过加载“日常预设”偷偷改了分辨率/倍率？
3. 分屏仍开但日常看不到关闭入口，是否让有效生成帧被隐性抑制？
4. 导出是否仍走旧startExport并停止前台？独立进程是否传齐全部设置，还是仅NR/SR/FG几个CLI开关？
5. 进度100%时是否真的完成mux、音轨和最终文件验证？取消是否只杀了UI而留下GPU进程？
6. 音量滑杆是否只是改了标签？采集音频路径与文件WASAPI是否分别有实际能力判断？
7. 快捷键是否抢走输入框的V、空格和方向键？隐藏控件是否还会提交设置？
8. 右栏收起/展开是否连续ResizeBuffers导致卡顿？暂停图片是否因为模式切换变黑？
9. UI字段、PresetStore和EngineController是否形成三份不同的设置真源？Applied失败时视觉是否仍显示成功？
10. 常驻性能更新是否同步文件I/O或GPU等待，导致UI新瓶颈？
11. “关闭增强”是否仍运行全负载，或者恢复时丢掉用户的模型/光流设置？
12. 在125/150%字体缩放与1366×768屏幕上是否有无法到达的导出取消/模式退出按钮？
13. 仅按钮改了中文，但错误、tooltip、焦点名称和导出状态是否还是原英文？
14. 既有SR4K+4X性能限制是否被改成漂亮的“240fps”理论数字？
15. 新文档中的“已实现/通过”是否有当前EXE和run ID，不是复制旧Phase或设计稿？
