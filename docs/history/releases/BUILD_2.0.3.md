# Veyra 2.0.3 corresponding source and build

Download the [v2.0.3 application source](https://github.com/Likely7/Veyra-NRVideo/archive/refs/tags/v2.0.3.zip) and [2.0.3 dependency source](https://github.com/Likely7/Veyra-NRVideo/releases/download/v2.0.3/Veyra-2.0.3-dependency-source.zip). Source downloads are for rebuilding; select the NVIDIA or AMD portable package to run the application.

The dependency bundle contains the byte-identical `Veyra-2.0.0-dependency-source.zip` (538838710 bytes, SHA256 `a293552434381a71169c1c27658f07202d67243ca82e748936b9db15077ce0de`) under `unchanged/`. Extract it for the existing Qt 6.8.3, patched FFmpeg/dav1d, Chiaki, Moonlight, Xbox/WebRTC, OpenSSL and FidelityFX 2.3.0 sources, ports, patches and SBOM. Follow [BUILD_2.0.0.md](BUILD_2.0.0.md) for these unchanged components. Preserve FFmpeg's PS5 H.264 32→256 slice patch and `veyra-local-build.json`. SoundTouch 2.4.1 and its static integration remain in the tagged application source; modifying it and rebuilding relinks the player.

New source materials include:

- Unmodified MIT lmxxf source from commit `78f548749e74824327b8458c57be31a1df78376a`. The actual build uses `src/LmxxfNrRuntime.cpp`, the public C ABI and upstream HIP/codec code. Veyra's `scripts/amd-nr/build-lmxxf-runtime.py`, `msvc-compat.h` and staging recipe accompany it. The build script accepts either the pinned Git checkout or the supplied `lmxxf-78f5487` source directory with its adjacent `source-manifest.json`; both are identity-checked. Compile with MSVC C++17 x64 `/O2 /LD /MD`, forced compatibility include, `NOMINMAX`, Windows 10 definitions and D3D12/DXGI/D3DCompiler/DXGUID/user32 libraries. Captured test images, measurement CSVs, weights and compiled kernels are excluded from the source archive. Model assets and HIP code objects are separate runtime payloads and retain their own terms. The RX9000 driver must provide HIP 7; no driver DLL is shipped.
- Both GPU packages retain the exact existing FidelityFX SDK 2.3.0 loader, upscaler and framegeneration components, at the user's explicit request to keep FSR3.1/4 together. Corresponding 2.3.0 sources are in the unchanged dependency archive. NVIDIA only exposes FSR3.1; FSR4 remains disabled there. No legacy SDK replacement or ABI compatibility change is shipped.

- MIT VFG sample reference `NVIDIA-Maxine/VFX-SDK-Samples` commit `52011f89c1741d06b40ea312af1f20be8be9ec62`, its notice, README and VideoFrameGenerationEffectApp.cpp. Veyra's own native loader, D3D12/CUDA shared buffers/fences, graph/worker integration and diagnostics are in the application source. Obtain the CUDA driver development headers from NVIDIA and point `VEYRA_CUDA_DRIVER_INCLUDE_DIR` at them. Proprietary NVIDIA SDKs, runtimes and models are excluded from source archives.

Use Visual Studio 2022 C++20 x64, Windows SDK, CMake/Ninja, Python 3.11 and Qt 6.8.3 MSVC2022 x64. Configure `x64-release` with QML, Remote Play, Moonlight and Xbox enabled and explicit external dependency paths as documented in BUILD_2.0.0. The display/project version is 2.0.3. Build `veyra_qml_ui` and the relevant acceptance targets; the source contains the executed tests/scripts and their bounded subprocess timeouts.

Both GPU packages use **the same executable, QML and shaders**. Run `package-qml-release.py --label 2.0.3 --no-archive` with explicit build/runtime/Qt/license/output paths to assemble fresh production assets. Then run `package-vendor-release.py stage` with `--common-stage`, `--runtime-source`, `--amd-source` and `--output`. After validation and committing the final source, use `refresh`, `finalize` and `archive` with explicit `--build` and `--seven-zip`. Publisher locks/manifests verify identities, signatures and source provenance; they do not prevent user DLL replacements. The script excludes opposite-vendor-only runtime files, driver DLLs, SDK development files, test executables and profiles, and checks every shipped runtime against its manifest. `package-2.0.3-dependency-source.py` generates the matching dependency source asset with a per-file hash manifest.

## 中文

重编译需同时下载上面的 **v2.0.3 应用源码** 和 **2.0.3 依赖源码包**。后者内嵌原样核验的 2.0.0 依赖包，并增加实际使用的 lmxxf MIT 源码/编译适配（FSR 2.3.0 对应源码沿用）和 MIT VFG 参考代码。Qt、patched FFmpeg、串流与 SoundTouch 构建材料保持完整；必须保留 PS5 slice 补丁。模型、HIP 内核和专有运行库与源码分开。AMD 推理仍需 RX9000 实卡验收；NVIDIA 的本机测试不能替代它。
