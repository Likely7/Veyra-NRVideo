# Veyra 1.4.0 — 相对公开发布的 1.3.0 的完整变更

> 状态：**本地构建的测试包**，供发布前人工验收。未推送、未发布、未上传 Release。
> 相对基线：公开发布的 **1.3.0**（tag `v1.3.0`）；中间给粉丝测的 1.3.1beta / 1.3.2beta1-4
> 都是测试包，不是公开发布。本文件按**功能区**汇总 1.3.0 到现在的 137 个提交。

## 1. 色彩页（本轮最大项，全新功能）

一条**全浮点、源头侧、单一融合 pass**的调色链，位置在所有效果器（超分/NR/补帧）之前：

- **总开关**：关闭时这条链**不存在**（不建表、不采样、零开销），开启但参数全中性时与旧链路
  **逐字节一致**（GPU 契约测试逐像素验证过）；
- **面板**（按 Lightroom 的观感与手感做的，UI 返工五批）：
  - 亮/颜色：曝光、对比度、高光、阴影、白色、黑色、色温（蓝↔黄渐变轨道）、色调（绿↔品红）、
    自然饱和度/饱和度（蓝→绿→黄→红）；滑块**双击复位 / Home 复位 / Alt 拖动精修**；
  - **曲线**：真编辑器——网格画布 + 可拖控制点（含**两端黑/白场点，x/y 都能拖**）+ RGB/红/绿/蓝通道 +
    “拉平”；插值是**单调三次样条**（Fritsch–Carlson，过点、C1 连续、不过冲、不反转），
    预览与烘焙**同一个函数**；
  - **混色器**：8 色系色点条，选中色系的**色相/饱和度/明亮度三根滑块同时显示**；“黑白”是一个开关，
    打开后画面转单色并出现该色系的“黑白”滑块。色带在**显示参考域**匹配（修掉了“调红色色相把脸也带走”：
    线性光 HSV 会把肤色从橙拉向红），半宽 32° + smoothstep 过渡；
  - **颜色分级**：四个色轮（阴影/中间调/高光/全局，色相-饱和度圆盘 + 明亮度条 + H/S/L 读数），
    双击复位该区；分区标题**吸顶**，滚动时不会被切一半；
  - **校准**：阴影色调 + 三原色色相/饱和度；
  - **LUT**：`.cube` 1D/3D 导入（校验后复制到 `runtime_local/luts`，写 manifest 含 SHA-256）、
    强度、输入空间（Cineon Log / sRGB / PQ）；**输入空间与内容域不匹配会被拒绝并提示**，
    不再静默乱套；
  - **分组“眼睛”**：每一组可临时停用（烘焙时按中性处理、**数值保留**），用于 A/B 某一组到底起了什么作用；
  - **一键还原 / 撤销 / 重做**（32 步历史）、**复制 / 粘贴**色彩设置、**按住看原图**
    （用中性调色实现，不重建管线）；
- **命名色彩预设**：保存/应用/删除 + `.vpcolor` 导出/导入（schema v19；旧文件按版本号继续可读）；
- **输出抖动**：进 8 位（1/255）与 10 位（1/1023）前加 TPDF 抖动，把量化误差变成噪声。
  实测：`contrast=-100` 压过的灰阶斜坡，最长连续相同码值 **16 px → 5 px**；
- **HDR**：调色在线性域、tone mapping **之前**（+1 EV 与独立 BT.2390 参考的误差 PQ 0.0012 / HLG 1.0e-5）；
  HDR 导出把源的 MaxCLL/MaxFALL 原样写进 `clli`；调色开启时**明确警告“未重算”**（不静默写错元数据）；
- **三入口一致**：截图 vs 导出帧 PSNR **51.9 dB**（调色开）/ **50.3 dB**（关）。

## 2. 1.3.0 之后修掉的问题（逐条，按用户看到的症状列）

### 2.1 播放 / 媒体

1. **IMAX/HEVC 的 MKV 打不开** → 新增 D3D11VA 硬解路径（私有 D3D11 设备解码、NT handle 共享给
   D3D12 图、GPU fence 同步不落 CPU）。实机：`IMAX…ZhiLuan.mkv` 3840×2024@60，12 秒 smoke
   696 帧 0 失败、音轨预填充正常。
2. 4K HEVC 播放/链路流畅度与字幕（含 MKV 封装字幕、独立字幕文件自动对齐）——多格式字幕引擎、
   双语言、样式、偏移与自动对齐整批接入（`79c1fa2`）。
3. **导出最后一帧/整槽缺帧导致失败** → CFR 整槽缺口补帧（重复上一帧，不伪造插值）+ 相位重锚；
   >2 槽或网格外仍硬失败。
4. **部分机器导出直接失败** → `6c70eb2`：NVENC apiVersion 回退、CFR 尾帧吸附、
   present-sink 补帧路径下的导出。
5. **PS5 串流“无法打开视频”**（首帧中止）→ `015f8a4` 修复音频入口插入语句改坏的 else 绑定。
6. **PS5 串流“连不上”、越重试越连不上** → PS5 会占用上一个会话约 20 秒（`RP_IN_USE`），
   旧退避 1/2/4 秒必然全撞窗口 → 改为 10/20/40 秒并在界面写明“正在释放上一个串流会话”。

### 2.2 采集卡

7. **OBS/抖音直播伴侣“识别不到 Veyra”** → 采集窗口标题被连接串覆盖（被当成文件名）→ 修复
   （`cd3e829`）。
8. **RGB24 采集倒像/画面变窄** → 直连 top-down 协商 + 手动上下翻转开关（`87ad4cd`、`015f8a4`）。
9. **原生格式（YUY2/NV12/RGB）采集只有 2 帧就反复重连**（1.3.2beta1 回归）→ 帧池改造误用到
   非压缩路径 → 修回邮箱轮转（`3eae1e1` / `3eafae1`）；四条路径各 2 分钟实机复测 0 丢帧。
10. **MPEG/MJPEG 采集延迟高** → 压缩格式不再走系统解码器：设备直连 + 自有解码 worker
    （有界队列丢旧保新）+ H.264/HEVC 走 D3D12VA + 帧池契约；图侧每帧 CPU P95 1080p 1.99→0.36ms、
    4K 6.22→0.92ms。
11. **解码 worker 复用调用方仍持有的帧**（会花屏/崩溃）→ `35e5593` 修复。
12. **N2“两次拷贝合并”实测负收益** → 整体回退（`383e1b5`），不把负优化留在产品里。
13. **采集颜色 A/B 工具双平面越界崩溃** → 修复，两条路径都能出对照图。
14. **H.264/HEVC 采集卡出不了画面** → in-band 参数集与 `MPEG2VIDEOINFO` 四种形态
    （Annex-B / avcC / hvcC / 长度前缀）全部解析。
15. 采集链路 N1/N3/N4（逐像素转换搬 GPU、格式排序与延迟档位、视频 pin 缓冲协商）；
    10bit 压缩输入暂时降位到 8bit 并写警告（HDR 压缩采集未实现）。

### 2.3 音频

16. **采集杜比/DTS 无声（5.1 用不了）** → 位流解码兜底：AC-3 / E-AC-3 / TrueHD / DTS / DTS-HD，
    含 IEC 61937 解框，解回 PCM 进既有 5.1 管线。
17. **采集音频入口无法选择** → 采集面板新增“采集音频（变更需重连）”：自动 / 强制线性 PCM / 位流优先。
18. **AVerMedia GC553G2/GC553PRO/GC575 的 5.1** → 武装非 PCM 载波直通 + 只读 IEC 61937 探针 +
    **按设备树识别**（不再依赖 DirectShow 路径）。**未过实卡（本机没有这几张卡）**。

### 2.4 帧生成 / 超分

19. **XeSS 选 2X 静默失效**（判成“无需解锁”→ 整档退回原生呈现，等于没补帧）→ 2X 走 Intel 原生路径。
20. **XeSS >2X 节奏不匀**（一串挤在一起 + 空一截）→ 交给提供方自己的调度器；
    4K/30fps 4X 实测同 burst 间距 mean 8.30ms（目标 8.33）。
21. **XeSS/FSR 切换与退出崩溃、区域不随缩放/平移** → `870358c`（view-aware 区域、提供方拆卸、
    切换上限）+ `0d3c073`（累计提交计数与应用侧 FG 计时）。
22. **RTX 30（解锁后）`FG.Available=false`** → NVAPI 架构伪装，30 系默认启用、失败自动回退；
    3060 上强制 CreateFeature 会挂住 → 改成 fail-closed（`298c306`）。
23. **40 系多帧上限**澄清：补丁后上报上限就是 5（6X），“仅 Blackwell”只是被跳过的一道分支。
24. **AMD FSR 补帧切不回 DLSS** → **1.4.0 直接从界面移除入口**（后端保留，旧设置自动回退 DLSS）。

### 2.5 色彩页（本轮新增功能，同时修掉的问题）

25. **调色参数不实时**（必须开关 NR 才生效）→ 引擎补上“同 revision 的实时 uniform 更新”路径。
26. **暂停时调整看不见** → 暂停路径用缓存源帧重新过一次图（色彩融在 ingest 里）。
27. **载入 `.cube` 概率闪退**（`0xC0000409`）→ 两个临时对象的区间构造越界读 → 一次转换。
28. **导出（视频+大图）完全不应用调色** → 两条导出链路漏了 `color` 字段。
29. 色彩页**预设/LUT 两个下拉永远是空的** → 控件挂在滚动面板上却按 window 的子窗口寻址。
30. **保存预设后选中项被清空** → 刷新下拉时固定重置。
31. **`.cube` 上传行距不满足 D3D12 的 256 字节对齐**（2/3/17/33 等尺寸全中）。
32. **改了 shader 却不重编译**（dxc 依赖漏了 `ColorGrade.hlsli`）→ 差点把颜色逻辑错误误判成代码问题。
33. **点曲线是折线不是曲线** → 换成单调三次样条（Fritsch–Carlson）。
34. **曲线暗部自带假“角度”** → 折线起点被初始化成画布左下角。
35. **曲线两端端点拖不动** → 端点 x/y 都放开（只受相邻点约束）。
36. **混色器调红色色相把脸也带走** → 色带改在显示参考域匹配 + 半宽 45°→32° + smoothstep。
37. **分组“眼睛”点了没反应** → 控件建到错误页 + 撤销分支的区间匹配吞通知。
38. **bypass 递归栈溢出** → 烘焙时忘了清 mask。
39. **颜色分级标题被滚动切一半** → 分组标题改为吸顶。
40. **色彩页一排灰滑条、不像专业工具** → 五批 UI 返工（渐变轨道、数值文本、四色轮、曲线编辑器、
    色点条、撤销/重做/复制/粘贴/按住看原图、面板默认更宽 320→392）。
41. **两个设置记忆缺陷**（`ui-preferences.v1` v3 写 6 读 5；NR 剔除区 inspector 范围 0..3→0..4）。

### 2.6 工具与基础设施

42. 工具层看门狗与内存闸：防止验证层挂住把内存打爆。
43. 版本号盖戳隐患：`VEYRA_DISPLAY_VERSION` 是 CMake cache 变量，改默认值不生效 →
    1.4.0 的 EXE 曾被盖上 `1.3.2beta4`；现在 cache 与项目版本不一致会强制对齐。

### 2.7 色彩页缺陷的根因对照表（细节）

| 问题 | 根因 | 影响 |
| --- | --- | --- |
| **调色参数不实时**，必须开关 NR 才生效 | 引擎只在 revision 变化时应用设置，而颜色参数按设计**不**改 revision（纯 uniform 更新）→ 渲染线程永远看不到 | 面板数字在动、画面不动（用户第一条验收反馈） |
| **暂停时调整看不见** | 调色融合在 ingest dispatch 里，暂停路径只重 present、不跑 process() → 新表没上传 GPU | “必须播放起来才看得到” |
| **载入 `.cube` 概率闪退** | 日志把 `lutNameString().begin()` 与另一个临时对象的 `.end()` 组成区间，长度是垃圾值 → 越界读（`0xC0000409`） | 任何用户选 LUT 都可能崩 |
| **导出（视频+大图）完全不应用调色** | 两条导出链路建图时漏了 `color` 字段 | 预览有调色、导出没有 |
| 色彩页预设/LUT **两个下拉永远是空的** | 控件挂在滚动面板上，却用 `SendDlgItemMessageW(window,…)` | 点“应用”永远提示先选预设 |
| 保存预设后**选中项被清空** | 刷新下拉时固定重置到“（未选择预设）” | 保存完立刻应用必然落空 |
| `.cube` 上传行距不满足 D3D12 的 256 字节对齐 | `rowPitch=size*16`（2/3/17/33 等常见尺寸全中） | 驱动可越界读写 staging buffer |
| **改了 shader 却不重编译** | `cmake/VeyraShaders.cmake` 的 dxc 依赖里没列 `ColorGrade.hlsli` | 改颜色核心头文件后程序继续跑旧 shader（差点误判成逻辑错误） |
| 点曲线是**折线不是曲线** | `pointCurve` 本来就是分段线性 | 曲线有硬角，画面效果也是折的 |
| 曲线暗部自带一个“角度” | 画折线时起点被初始化成画布左下角，而不是曲线在 x=0 的值 | 预览撒谎（实际处理是对的） |
| 分组“眼睛”点了没反应 | 控件建到了错误的检查器页 + 新的撤销分支用区间匹配吞掉了它的通知 | 功能不可用 |
| 调色链与参数烘焙**递归栈溢出** | bypass 分支里 `bake(masked)` 忘了清 mask | 单元测试直接崩 |

## 3. 补充细节：导出 / 媒体兼容

- **CFR 整槽缺口补帧**：导出遇到“落在网格上、前移 1–2 槽”的缺帧时，用**上一帧真实画面重复**补齐
  （重复而非伪造插值，PSNR 43.6 dB vs 洞后第一帧 20.5 dB 证明是重复），补完重锚相位；
  >2 槽或网格外抖动仍硬失败。修复了“导出跑到 99% 失败/尾部缺帧”这一类反馈；
- **IMAX/HEVC MKV 打不开**：新增 **D3D11VA 硬解路径**（私有 D3D11 设备解码、NT handle 共享给 D3D12 图、
  GPU fence 同步不落 CPU）。实机验证：`IMAX.Laser.Pre.Show.New.2160P.DDP5.1.Atmos-ZhiLuan.mkv`
  → HEVC 3840×2024@60 正常解码，12 秒 smoke `frames=696 failed=false processedFps=60.00`；
- 4K HEVC 播放链路与字幕（含 MKV 封装字幕、独立字幕文件自动对齐）在前几轮已修/已加。

## 4. 补充细节：音频

- **AVerMedia GC553G2 / GC553PRO / GC575 的 5.1 直通**：按设备树（不是 DirectShow 路径）识别采集卡，
  武装非 PCM 载波，让 Dolby/DTS 位流原样进接收端；另加**只读 IEC 61937 载波探针**用于诊断。
  **注意：本机没有这几张卡，只有单元测试通过，必须由持卡用户实测。**

## 5. 补充细节：采集链路与实测

- N1 逐像素转换搬到 GPU、N3 格式排序与延迟标注、N4 视频 pin 缓冲协商（N2 实测负收益已整体回退）；
- MPEG/压缩链：MJPEG 设备直连 + 自解码 worker + D3D12VA 后端 + 帧池契约（都有 2 分钟真机复测）；
- 1080p YUY2 实测：调色链路开/关各 2 分钟——**每帧多 0.037 ms GPU 时间**，软件侧
  ingress→present-return 延迟**无可测变化**，两轮均满 60 fps、零丢帧。

## 6. 补充细节：帧生成 / 超分

- 能力驱动的 **2X–6X** 多帧生成；XeSS MFG 解锁（OptiScaler XeFG 移植，带 provider 身份与回滚）；
- RTX 30（Ampere）架构伪装路径与 3060 实机排查；40 系 MFG 解锁研究；
- AMD FSR 超分（3.1.x，N 卡可用）接入 SR 阶段；
- **1.4.0 移除项**：**AMD FSR 补帧的界面入口已删除**（用户反馈切回 DLSS 容易卡住、效果一般）。
  引擎后端保留（`--fg-fsr`、探针仍可用），旧设置里若存了 FSR，打开时自动切回 DLSS 并在日志写明。

## 7. 已知边界（不要当成已通过）

1. Glass-to-glass（采集卡→屏幕）延迟**没有物理测量**；上面的 0.037 ms 是进程内指标；
2. AVerMedia 5.1 直通未过实卡；10-bit P010、AMD/Intel 组合、长片整段播放未测；
3. 色彩页 P1 的 P2/P3 项（纹理/清晰度/去朦胧、点颜色、镜头配置文件等）未做；
4. HDR 导出的 MaxCLL/MaxFALL **未重算**（只原样带上并标注）。
