# HDR 补帧兼容：默认关闭的设置开关

用户要求将 HDR 闪黑兼容候选改为设置页开关、默认关闭。已在“设置 → 兼容”增加“HDR 补帧闪黑兼容”，保存为全局偏好 `hdrFgCompatibility`，新配置和没有该字段的旧配置均关闭。画质预设、节点和导出设置不接管这个选择。

## 行为与代价

默认继续直接呈现，不分配兼容合成纹理。用户开启且输出满足 NVIDIA HDR10 应用侧补帧条件时，才使用单张 GPU 合成纹理 → 交换链复制。非适用输出保留选择，实际路径不启用。使用既有 presentation revision 传递到 GPU 所属线程，允许播放中切换；仅切换时排空呈现队列，关闭后释放该纹理。切换可能短暂停顿，正常逐帧没有新增 CPU 等待、睡眠或像素回读。

4K 兼容纹理实际分配 33,423,360 字节（31.875 MiB），固定复用。开启后每次显示增加 GPU 图像复制与屏障，可能增加带宽、GPU 耗时及满载时的延迟；不保证零开销。分配失败或切换排空失败记录日志，effective 设置反映实际路径，保留有效呈现。没有做真实 OOM/显存压力测试。

随包 Compatible/Direct 启动器改为设置私有配置中的同一个布尔值，移除环境强制；正常设置不依赖环境变量。仅原生回归保留测试覆盖变量。启动器保持原 EXE 名字和用户原配置。

RTX5070 / 616.56，普通单进程串行负载，无竞争或压力测试。缓存产品为已验 71723e0，未改缓存原件。按 Ninja 实际头依赖重新编译 13 个生产消费者及新的翻译资源，然后链接 GUI；GUI SHA256 `8f69759434fe96036d768755db3d890307321f47f188e33a40ccc9d9bbe43e00`。测试 fixture 单独重编后 native SHA256 `108e827fcace3d9d09c019ffa8dd5c3ca881f9d40a94037dc00a9e9579f3ffd6`，GUI 保持。

- 真实 QML/bridge 五次运行：新配置关闭 → 开启保存 → 重启恢复开启 → 关闭保存 → 重启关闭；旧配置缺字段关闭；其它显示设置不擦除选择、哨兵偏好保留；英文翻译从 EXE 内新资源加载。各进程约 8 秒、exit0，无 QML 错误。测试调用真实组件 toggled 信号，不冒充人工鼠标点击。设置页稳定截图已查看，控件显示正常、默认关闭。
- HDR DLSS 4K 交换链与 HDR VFG 4K 交换链：各 512 原帧 / 620 生成帧、94 次无损 10-bit 窗口对照，最大 RGB 码值误差 0，D3D12 错误 0。包括默认 false、启用、关闭、再次启用；窗口/全屏、resize、reset 与销毁顺序。4K 是输出缓冲验证，测试输入 640×360 P010，不宣称 4K NR 或物理 HDR 显示验收。

## 失败与边界

构建包装脚本初次把 `/implib:` 输出选项当输入库；之后翻译资源的 `.qt/rcc` 路径及 Windows 分隔符识别错误，均在最终链接前中止。修正后构建成功，未写缓存。原生回归新增像素检查落在 800×450 resize 窗口内，错误与 640×360 原图逐位比较而失败；将检查移到恢复相同尺寸后，仅重编测试并通过，产品 GUI 没改。首张 UI 截图拍在入场动画完成前，只能证明组件存在；补取稳定截图确认实际可见布局。没有把这些测试环境错误当现场闪黑原因。

HDR 闪黑根因未确认，用户 RTX5090 尚未回测本兼容候选；不能承诺开启必然解决、所有显卡通过或屏幕延迟不变。NVIDIA 持续显存增长仍未定位。BMD 另一项兼容候选的实卡黑屏和延迟仍需测试。用户已授权本地 main 整合，最终合并提交、组合构建/回归及保全结果见 docs/MERGE_MAIN_2026-10-09.md；未推送或发布新版本。
