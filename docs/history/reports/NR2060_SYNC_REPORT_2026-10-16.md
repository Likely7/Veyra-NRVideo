## 现场结论与证据边界

`logs(19).zip` 中的 RTX 2060 在驱动 610.88、617.42 两个版本下，54 次光流初始化均成功，随后全部在第一个输入资源注册时返回 `NV_OF_ERR_INVALID_PTR`（4），引擎因此关闭依赖光流的 NR。2345 条采集统计中的 NR、NVOF 执行数均为 0，尚未进入 SF-v2 NR 初始化。因此，现场“等待样本”首先是光流初始化链路失败，不是 NR 算得太慢。

旧注册代码只传了资源和返回句柄，遗漏 D3D12 注册接口的输入、输出同步点。本次按 NVIDIA SDK 的同步契约补齐。日志能证明失败位置和代码缺口，尚不能证明这就是该 2060 的唯一故障原因，也不能把一位用户的情况推广为全部 20 系不支持。两版驱动均失败，单凭这份日志也不能认定 NVIDIA App 设置是原因。

原始诊断与逐会话计数位于 `E:/项目/Veyra/reports/nr2060-waiting-20261016/`。接口参考：[NVIDIA NVOF Programming Guide](https://docs.nvidia.com/video-technologies/optical-flow-sdk/nvofa-programming-guide/index.html)。

## 修改

1. `NvOfSession::initialize()` 为资源注册传入有效输入、输出 fence。四资源及双向六资源注册按独立完成计数衔接，初始化成功或部分失败回滚前确认已提交注册完成。
2. 注册使用独立 fence，不占用正常光流输出 fence，也不提前宣告“已经有一帧光流结果”。首次光流执行仍从完成值 1 开始。
3. 初始化确认只有一次有界等待，异常等待上限 5 秒；正常逐帧 `execute()` 与基线逐字一致，没有新增逐帧 CPU 等待、像素回读、额外图像处理或显示队列。初始化多了同步资源和完成确认，不能宣传为绝对零开销。
4. 注册失败记录 SDK 错误详情、HRESULT、同步点及回滚结果。增加默认不生效的 `VEYRA_TEST_NVOF_REGISTER_FAILURE` 定向失败入口，用来验证部分注册回收；日志明确标为测试注入，不冒充实际硬件故障。
5. 引擎已确认 NR 初始化失败并回退时，列表和节点显示“启用失败”，节点悬停可查看现有后端原因；不继续等待计时、不显示旧毫秒数。正常暖机、计时、禁用、未播放和草稿状态沿用，用户 NR 参数保留。
6. 新提示补齐英文、日文、繁体中文。既有 33ms/250ms 刷新周期、默认 GPU 优先级、光流算法、NR 模型、帧生成与显示调度均未修改。
