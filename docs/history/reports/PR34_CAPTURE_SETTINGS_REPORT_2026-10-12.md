## 解决的缺口

- 旧枚举只读取 `IAMStreamConfig::GetStreamCaps` 每条能力记录中的默认帧间隔，另外还过滤了大于 3840×2160 的条目。现在结合驱动公开的 `IAMVideoControl::GetFrameRateList` 展开离散帧率，保留原始媒体类型索引、扫描类型和精确 100ns 间隔；不根据 min/max 范围虚构常用帧率，不使用固定分辨率表。未提供该可选接口的驱动继续使用它上报的原始类型。
- 分辨率、帧率、像素格式只组合设备实际报告的媒体类型。相同数字的逐行／隔行模式、不同字段顺序与同名像素格式保留独立身份。旧格式键只有唯一匹配时迁移，不能唯一确定时要求重新选择。连接时使用所选精确帧间隔；设备帧率填 0 不会退回能力记录的另一帧率。
- 超出播放器接入能力的尺寸／已知原始像素布局仍显示，但标为不支持、禁止连接；列出能力不代表新增 8K 播放承诺。BMD 自动模式显示“自动检测实际信号／跟随实际信号／自动选择像素格式”，不再显示 0×0 或 0fps。原生模式列表保留卡上报的全部制式，自动初始化只选播放器可接入的尺寸。
- 设备、所选媒体类型、显式音频输入、设备帧率、色彩／范围均在修改时保存，不再依赖“连接并开始”。翻转、转 SDR、设备缓冲和音频入口模式作为跨列表／节点模式的全局设置保存，并在启动自动恢复之前还原。既有 Blackmagic／美乐威偏好保留。
- “继续上次”和启动自动恢复共用恢复路径，使用最新保存的表单。缺失设备、媒体类型或音频端点时保留原记录并提示，不静默换卡、换格式或改成静音。另修复失效格式没有活动选择时，修改其他控件会清空旧格式键的边界情况。
- 设置文件使用 `QSaveFile` 原子替换；保存失败会提示。连续刷新／切换设备只保留最新待查询请求，避免旧异步结果覆盖最终选择。原有 33ms 统计、约 250ms 状态更新、默认 GPU 优先级、采集队列／缓冲及逐帧处理保持。
- 相对 main 增加 42 个完整的繁中／英文／日文翻译键。消除 PR 与 main 自动合并产生的“逐行”重复键，保留 main 原值和两个旧采集标签；既有翻译值没有被覆盖。

## 失败、修正与未验范围

两次早期 GUI 夹具失败均保留原日志：`ui-edit-20261012-141307` 在关闭时脱离可视树的对话框上查找对象失败；`141332` 错把没有运行来源时的待应用配置当作必须等待的播放事务，85 秒自动退出而没有 PASS。只修私有夹具：从 Main.qml 的实际 dialogs 引用打开，空闲表单检查不等待运行中的帧事务。后续未连接保存和最终 9 组真实 GUI 全通过，生产程序没有加入测试 Timer／Loader。私有 profile 准备脚本首次按带 BOM 的 UTF-16 读取无 BOM 文件失败，改为产品实际 UTF-16LE；未改产品文件格式。自动合并工作树创建尚未结束时，提前执行的 merge 被 index.lock 拒绝；等待创建完成后正常合并，没有手工删除锁或重置既有目录。

对抗式审查发现并修掉了失效格式键被其他控件保存清空的问题，以及 PR/main 翻译重复键。保留审查断言失败及最终复核结果；不以第一次编译通过替代验收。

本机没有 BMD／美乐威实卡，因此原生自动识别、HDMI／SDI 输入切换、各卡所有格式的真实出画仍需对应持卡用户验证。本轮验证了枚举、参数恢复、错误处理和本机 USB 采集连接，没有做跨显卡、长时间、端到端延迟或性能提升承诺。驱动未公开的私有格式与连续能力区间无法凭空枚举为有限列表；界面列出的是驱动公开的离散能力。
