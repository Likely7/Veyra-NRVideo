## 依据（调研时实测）

- VFG 的每张子帧都是一次完整推理：4K Medium 每张约 3.55 ms，2X、4X、8X 都一样。按 NVIDIA 官方样例的方式调用、每张换输出、同一张重复调用，结果全都一样，说明 SDK 内部没有任何跨子帧缓存。外部无法让它“重的部分只算一次”。
- 产品原来开着 `AutomaticShotChangeDetectionEnabled=1`。这会让每次 `NvVFX_Run` 等 GPU 跑完才返回：主机耗时约 3.5 ms，关掉后 0.13 ms。而且检测在每张子帧上重做一遍，每张多约 0.2 ms GPU。
- 详见 `reports/vfg-deep-opt-20261011/方案选项.md` 以及 `logs/claude-vfg-deep-20261011/*.json`。

## 改动

### 1. GPU 镜头切换判断，替代 SDK 自带检测

- 新着色器 `shaders/VfgShotChange.hlsl`：用 VFG 自己读取的 A/B 两份编码输入缓冲，各取 64×36 个亮度点，计算 256 级直方图距离（L1/2）和归一化 SAD。阈值和“闪光不算切换”的规则与 CPU 路径的 `core::SceneCadenceAnalyzer` 完全相同，阈值由 C++ 的 `Config` 默认值传入。
- 每对 A/B 只在 `capture()` 的同一个命令列表里跑一次（1 个线程组），不随子帧重复。结果写进一个 64 位标志。
- `copyOutput()` 用 D3D12 predication 在 GPU 上选择拷贝源：没有切换就拷 VFG 输出；有切换就拷当前输入 B，这与 SDK 自带检测的行为一致。全程没有回读，CPU 不等待，也没有额外 pass。
- 现在所有来源都有切换判断。原来 Veyra 自己的判断只在 CPU 有画面的路径（采集、软解）上运行，硬解只能依赖 SDK 自带检测。图里原有的 `ShotChange`（重置、拖动、CPU 判定的切换）保持不变；重置对传 `comparePrevious=false`。
- SDK 自带检测改为关闭。测试开关 `VEYRA_TEST_VFG_AUTO_SHOT_CHANGE=1` 可恢复旧行为（打开 SDK 检测、跳过 GPU 判断），用于同一个 EXE 的 A/B。

### 2. 混合档位（vfgQuality 3–5）

| vfgQuality | 名称 | 中间那张子帧 | 其余子帧 |
| --- | --- | --- | --- |
| 0 / 1 / 2 | 低 / 中 / 高 | 同一个模型 | 同一个模型 |
| 3 | 高+中 | 高 | 中 |
| 4 | 高+低 | 高 | 低 |
| 5 | 中+低 | 中 | 低 |

- 每对原帧只有一张子帧用前一档模型：偶数倍率是 t=1/2 那张，奇数倍率是紧挨中点之后的那张；2X 只有一张子帧，所以就是前一档。其余子帧用后一档。依据是插值误差在正中间最大，越靠近真实帧越小。
- 实现：VfgBackend 加载第二个 NvVFX 实例（后一档模型），两个实例共用同一条 CUDA 流，所以 CUDA 工作仍然串行，生产者/完成栅栏都不变。每个实例每对输入只绑定一次（`pairSerial`），绑定规则与 NVIDIA 样例一致。
- 设置：`EnhancementSettings::vfgQuality` 的合法范围是 0–5，辅助函数为 `vfgMixedQuality`、`vfgPrimaryMode`、`vfgSecondaryMode`、`vfgPrimarySubframe`。bridge、列表页和节点页的“VFG 质量”下拉增加“高+中 / 高+低 / 中+低”，提示文字同步更新；四种语言都已翻译。
- 状态提示：混合档显示“VFG 中间帧约 X ms、其余每张约 Y ms，当前负载约可稳定 NX”，按一张前一档加若干张后一档估算。
- 测试画像（`VEYRA_TEST_VFG_GPU_PROFILE`）里，后一档的运行时间单独记为 `runSecond`。
- 旧版本兼容：2.0.6 及更早版本不认识 3–5。打开含混合档的预设库或会话时，会提示“预设库补帧后端或倍率无效”，并按现有逻辑**拒绝覆盖原文件**，所以用户预设不会被抹掉。

## 未验证与边界

- 混合档的**实际观感**：每张子帧都是官方模型的原样输出，但相邻子帧来自不同档，细纹理、头发、字幕边缘可能出现可感知的“呼吸”或闪动。需要用户实际观看判断，所以保留为可选档，默认仍是“中”。
- 只在 RTX 5070 上测过。其他显卡（特别是 40 系和显存 8 GB 的卡）的耗时和显存未测；带“高”的两档需要同时加载高档模型。
- 只测了文件播放（4K30），没测采集卡和 60fps 片源，也没有测 HDR 的实际播放（10 位格式只在 GPU 测试里覆盖）。
- GPU 镜头切换判断与 CPU 路径同指标、同阈值，但取样点来自增强后的画面；硬解来源以前靠 SDK 检测，两者对“软切换”（淡入淡出等）的判定可能不同。
