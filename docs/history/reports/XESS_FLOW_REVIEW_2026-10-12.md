## 2. “默认光流 1080p”是不是原因：不是

- **产品默认**：4K 源在实时 NR 策略下，光流尺寸等于 NR 尺寸 1920×1080（`ResolutionPlan`）。每个 NVOF 向量覆盖 4K 画面的 8×8 像素块。
- **证据 1，运动误差**（下文“无窗口运动质量测试”，侧跑 80 px/帧，半分辨率 → 全分辨率，即 1440p 测试里的 1080p 等价 → 4K 等价）：
  - 修复前光流：总 EPE 4.69 → 4.47；
  - Codex 版：3.09 → 3.06；
  - 本版在全分辨率下反而变差：背景横移露出区 7.6 → 16.7，因为填补的搜索半径按光流像素计。
- **证据 2，XeSS 实测**（J0）：修复前光流改用全分辨率，轮廓带误差 8.2148 → 8.1977，基本没变。
- **代价**：NVOF 1080p 约 0.84 ms，4K 约 2.97 ms（09-08 实测）；而且会改变 NR 使用的光流输入。
- **结论**：不建议改默认光流分辨率。

## 4. 改进：NVOF 前后向一致性判定露出区

**做法**
- 仅在 XeSS + 运动来源“光流” + NVIDIA NVOF 时，让 NVOF 同时输出后向光流（`NV_OF_PRED_DIRECTION_BOTH`，现有 `NvOfSession` 已支持）。
- FlowRefine 的候选选择与 Codex 版完全相同（颜色代价）。选定后，查后向光流：当前像素按选定向量落到上一帧，再按那里的后向向量回到当前帧，偏离多少记为“前后向不一致量”。
- 新露出的背景没有任何向量能前后一致：
  - 真实向量落在当时挡住它的人物上；
  - 人物的向量落在已经移走的背景上。
- FlowFill 规则：
  - 不一致量 > 2 光流像素，或颜色代价 > 0.06：填补；
  - 只有不一致量 ≤ 0.5 且代价 ≤ 0.06 的像素可以提供向量（一致的背景、身体 P90 约 0.2）；
  - 在同色、一致的邻近像素里取向量。

**影响范围**
- NR/SR 的光流逐字节不变（Codex 合同测试第 160 项检查）；其他补帧、AMD 光流、GPU DIS、“自动”（零运动）都不变。
- 测试开关：`VEYRA_TEST_FLOW_CONSISTENCY=0` 恢复 Codex 版；`VEYRA_TEST_FLOW_REFINE=0` 恢复修复前光流。

**撤回或未采用的尝试**（同一 EXE，同场景 A/B）
- **一致性参与候选选择**：密集竖条 9.7037 → 9.9149，负收益。撤回，改为只用于判定填补。
- **填补额外要求代价下限**：只是把露出区误差和四肢误差互换。撤回。
- **触发阈值 4 或 8 px**：与 2 px 无差异，保留 2。
- **来源阈值 2 或 0.25**：与 0.5 基本一致，保留 0.5。

### 开关「边缘神盾」（Edge Aegis）

- **位置**：
  - 列表模式：补帧页 →「光流 · 运动估算」→「光流算法」下面一行；
  - 节点模式：「输入 · 光流」卡，光流算法下面。
- **行为**：
  - 默认开启；关闭即修复前的光流；
  - 只在 XeSS 补帧、运动来源“光流”时起作用，此时切换会重建处理图。其他组合不受影响，也不会因为它重建（`activeVideoSettings` 把它视为非活动设置）。
- **保存方式**：与 NR 抗闪烁、音频同步一样，作为全局控件存进界面偏好 `qml-preferences.v1.json` 的 `edgeAegis`，启动时在会话之后恢复。会话和预设文件格式都不改，旧版本读取不受影响。
- **代码链路**：`EnhancementSettings::fgMotionRefine` → `GraphDescription` → `EnhanceGraphDesc::fgMotionRefine`，以及桥接属性 `edgeAegis`。
- **翻译**：繁中、英、日。只追加本次 4 条；本分支的 catalog 与全量提取本来就不同步，所以没有运行 `extract.py`。

### AMD（FidelityFX）光流

**FlowRefine 读取 FidelityFX 向量**
- 网格 8，整像素；
- 与 NvofDensify 同样处理：预热帧和场景切换历史期间输出零运动。

**露出区检测：新增 `FlowClaim.hlsl`**

FidelityFX 只算单向，没有后向光流。改用“认领”检查，每帧三次派发：
- **清零**；
- **认领**：每个光流像素认领它落到的上一帧位置。按颜色代价排序，用 `InterlockedMax`，代价最低者得；
- **结算**：记录每个像素的向量与认领胜者向量的差，供 FlowFill 使用，与 NVIDIA 的前后向差同一阈值（>2 填补，≤0.5 可借出）。

原理：新露出的背景无论带哪个向量，落点都被别的像素以更好的匹配占着：
- 落在人物上，人物还在原地，与自己完全匹配；
- 落在移走的背景上，被现在显示那块背景的像素认领。

这两种情况下它的向量都与胜者不同。同向的像素（取整、缩放）差为 0，不受影响。

**其他**：测试开关 `VEYRA_TEST_FLOW_CONSISTENCY=0` 同样关掉 AMD 的认领检查。
